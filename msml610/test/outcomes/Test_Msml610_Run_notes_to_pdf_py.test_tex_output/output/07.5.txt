\begin{frame}{Models as Maps of the Real World}
\protect\phantomsection\label{models-as-maps-of-the-real-world}
\begin{itemize}
\item
  Typically you need to compare models to understand which one is
  \textbf{\textcolor{red}{"better"}}
\item
  Models are a \textbf{\textcolor{darkgreen}{map, not a copy}} of the
  real world

  \begin{itemize}
  \tightlist
  \item
    \emph{``All models are wrong, but some are useful''} (Box, 1976)

    \begin{itemize}
    \tightlist
    \item
      ``Wrong'': all models are wrong since they aren't the actual
      territory
    \item
      ``Useful'' some models describe a problem better than others
    \end{itemize}
  \end{itemize}
\item
  Models have a \textbf{\textcolor{blue}{purpose}}

  \begin{itemize}
  \tightlist
  \item
    Are approximations to understand a problem
  \item
    A model can't reproduce all aspects equally well
  \item
    Different models capture different data aspects
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bayesian P-Value for a Statistic}
\protect\phantomsection\label{bayesian-p-value-for-a-statistic}
\begin{itemize}
\item
  A Bayesian p-value summarizes the comparison between simulated and
  observed data
\item
  \textbf{\textcolor{red}{Procedure}}

  \begin{itemize}
  \tightlist
  \item
    Given the posterior predictive \(\tilde{Y}\)
  \item
    Choose a summary statistic \(T\) (E.g., mean, median, standard
    deviation)
  \item
    Compute \(T\) for:

    \begin{itemize}
    \tightlist
    \item
      The observed data \(T_{obs}\)
    \item
      The simulated data \(T_{sim}\) from the posterior predictive
    \end{itemize}
  \item
    Compute the Bayesian p-value as the portion of simulated datasets
    where the test statistic is smaller than the observed data: \[
    \text{Bayesian p-value} \defeq \Pr(T_{sim} \ge T_{obs} | \tilde{Y})
    \]
  \item
    If observed values agree with predicted ones, the value should be
    around 0.5
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bayesian P-Value for Entire Distribution}
\protect\phantomsection\label{bayesian-p-value-for-entire-distribution}
\begin{itemize}
\item
  Instead of using a summary statistic, one can compute ``the
  probability of predicting a lower or equal value for each observed
  value''
\item
  If the model is well calibrated, it captures all observations equally
  well, the probability should be the same for all observed values

  \begin{itemize}
  \tightlist
  \item
    The output should be a uniform distribution
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bayesian P-Value: Example}
\protect\phantomsection\label{bayesian-p-value-example}
\begin{itemize}
\item
  Study the height of people in a population
\item
  \textbf{\textcolor{red}{Fit the Bayesian model}}

  \begin{itemize}
  \tightlist
  \item
    Assume a normal distribution with unknown mean and variance
  \item
    Collect observed data of heights (e.g., 100 people)
  \item
    Specify a prior distribution for mean and variance
  \item
    Combine observed data with prior to obtain a posterior distribution
    of mean and variance of population height
  \end{itemize}
\item
  \textbf{\textcolor{blue}{Compute Bayesian p-value}}

  \begin{itemize}
  \tightlist
  \item
    From posterior distribution:

    \begin{itemize}
    \tightlist
    \item
      Generate new simulated datasets
    \item
      For each dataset, compute mean height
    \end{itemize}
  \item
    Use test statistic \(T\), as the difference between the mean of the
    replicated dataset and the observed mean
  \item
    Compute Bayesian p-value: the proportion of replicated datasets
    where the test statistic is \textgreater= test statistic for
    observed data

    \begin{itemize}
    \tightlist
    \item
      A value close to 0.5 means the observed data is covered by the
      model
    \item
      A value close to 0 or 1 indicates a poor fit
    \end{itemize}
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bayesian vs Frequentist P-Value}
\protect\phantomsection\label{bayesian-vs-frequentist-p-value}
\begin{itemize}
\item
  \textbf{\textcolor{red}{Frequentist p-value}} is the probability of
  getting observed data as or more extreme, assuming the null hypothesis
  is true
\item
  \textbf{\textcolor{blue}{Bayesian p-value}} is the probability that
  simulated data from the model (i.e., posterior predictive check) is as
  or more extreme than the observed data
\item
  P-value measures inconsistency between observed data and:

  \begin{itemize}
  \tightlist
  \item
    A null hypothesis (frequentist approach)
  \item
    Model (Bayesian approach)
  \end{itemize}
\item
  Does p-value incorporate uncertainty?

  \begin{itemize}
  \tightlist
  \item
    (Frequentist) No, it uses single point estimates
  \item
    (Bayesian) Yes, it incorporates uncertainty of parameter estimates
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Occam's Razor}
\protect\phantomsection\label{occams-razor}
\begin{itemize}
\tightlist
\item
  \emph{``If you have \textbf{\textcolor{red}{equivalent}} explanations
  for the same phenomenon, you should choose the
  \textbf{\textcolor{darkgreen}{simpler}} one''}

  \begin{itemize}
  \tightlist
  \item
    Quality of explanation \(\approx\) accuracy
  \item
    Simpler \(\approx\) number of model parameters
  \end{itemize}
\item
  \textbf{\textcolor{blue}{Complexity vs accuracy}}

  \begin{itemize}
  \tightlist
  \item
    Increasing model complexity (e.g., number of model parameters) is
    accompanied by:

    \begin{itemize}
    \tightlist
    \item
      Increasing in-sample accuracy
    \item
      Not necessarily out-of-sample accuracy
    \end{itemize}
  \item
    The complex model:

    \begin{itemize}
    \tightlist
    \item
      Did not ``learn'' from the data but just ``memorize'' it
    \item
      Does a bad job generalizing to predict potentially observable data
    \end{itemize}
  \end{itemize}
\item
  Ideally balance complexity and accuracy in a quantitative way
\end{itemize}
\end{frame}

\begin{frame}{Overfitting and Underfitting}
\protect\phantomsection\label{overfitting-and-underfitting}
\begin{itemize}
\tightlist
\item
  A model is \textbf{\textcolor{red}{overfit}} when it has many
  parameters, fitting the training data well but unseen data poorly

  \begin{itemize}
  \tightlist
  \item
    Overfitting in terms of signal/noise:

    \begin{itemize}
    \tightlist
    \item
      Each dataset has ``signal'' and ``noise''
    \item
      We want the model to learn the signal
    \item
      A model overfits when it learns the noise, obscuring the signal
    \end{itemize}
  \end{itemize}
\item
  A model is \textbf{\textcolor{blue}{underfit}} when it has few
  parameters, fitting the dataset poorly

  \begin{itemize}
  \tightlist
  \item
    An underfit model doesn't learn the signal well
  \item
    E.g., a constant fits a dataset, only learning the mean
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bias-Variance Trade-Off}
\protect\phantomsection\label{bias-variance-trade-off}
\begin{itemize}
\tightlist
\item
  A model has \textbf{\textcolor{red}{high bias}} when:

  \begin{itemize}
  \tightlist
  \item
    It has low ability to accommodate the data
  \item
    I.e., underfitting
  \item
    E.g., a polynomial of degree 0
  \end{itemize}
\item
  A model has \textbf{\textcolor{blue}{high variance}} when:

  \begin{itemize}
  \tightlist
  \item
    It has high capacity and it is sensitive to details in the data,
    capturing noise
  \item
    I.e., overfitting
  \item
    E.g., a polynomial of degree 100
  \end{itemize}
\item
  Trade-off between bias and variance

  \begin{itemize}
  \tightlist
  \item
    Goal: balance simplicity and goodness of fit
  \item
    Aim for a model that ``fits the data right,'' avoiding overfitting
    or underfitting
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Maximum Likelihood Estimation (MLE)}
\protect\phantomsection\label{maximum-likelihood-estimation-mle}
\begin{itemize}
\tightlist
\item
  \textbf{\textcolor{red}{MLE}} finds the parameter values that make the
  observed data most probable (given a model)

  \begin{itemize}
  \tightlist
  \item
    Denoted by \(\hat{\theta}_{MLE}\)
  \item
    It's a point not a distribution
  \end{itemize}
\item
  \textbf{\textcolor{blue}{Procedure}}:

  \begin{itemize}
  \tightlist
  \item
    Given the data \(x_1, x_2, ..., x_n\)
  \item
    Assume it comes from a distribution with an unknown parameter
    \(\theta\)
  \item
    Pick the value of \(\theta\) that makes the data most likely given a
    likelihood function \begin{equation*}
    \begin{cases}
      L(\theta) = \log \Pr(x_1, x_2, ..., x_n | \theta) \\
      \hat{\theta}_{MLE} = \argmax_{\theta} L(\theta) \\
    \end{cases}
    \end{equation*}
  \end{itemize}
\item
  In Bayesian terms, MLE is equivalent to the mode of \(\theta\) using
  flat priors

  \begin{itemize}
  \tightlist
  \item
    Aka MAP (maximum a posteriori)
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Akaike Information Criterion (AIC)}
\protect\phantomsection\label{akaike-information-criterion-aic}
\begin{itemize}
\item
  AIC is defined as

  \[
  AIC = -2 \sum \log \Pr(y_i | \hat{\theta}_{MLE}) + 2 \text{num}_{params}
  \]

  where:

  \begin{itemize}
  \tightlist
  \item
    \(\hat{\theta}_{MLE}\) is the maximum likelihood estimation of
    \(\theta\)
  \item
    \(\text{num}_{params}\) is the number of parameters
  \end{itemize}
\item
  \textbf{\textcolor{red}{Interpretation}}:

  \begin{itemize}
  \tightlist
  \item
    The first term (log likelihood) measures how well the model fits the
    data
  \item
    The second term penalizes complex models
  \end{itemize}
\item
  \textbf{\textcolor{blue}{Cons}}:

  \begin{itemize}
  \tightlist
  \item
    Discard information about uncertainty of posterior estimation
  \item
    MLE assumes flat priors (vs informative and weakly informative
    priors)
  \item
    Number of parameters is not always a good measure of complexity

    \begin{itemize}
    \tightlist
    \item
      E.g., in hierarchical models the effective number of params is
      smaller
    \end{itemize}
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bayesian Information Criteria}
\protect\phantomsection\label{bayesian-information-criteria}
\begin{itemize}
\tightlist
\item
  \textbf{\textcolor{red}{Bayesian Information Criteria (BIC)}}

  \begin{itemize}
  \tightlist
  \item
    Like AIC, it assumes flat priors and uses MLE
  \item
    It is not Bayesian
  \end{itemize}
\item
  \textbf{\textcolor{blue}{Widely Applicable Information Criteria (WAIC)}}

  \begin{itemize}
  \tightlist
  \item
    Bayesian version of AIC
  \item
    It has two terms:

    \begin{itemize}
    \tightlist
    \item
      One that measures how good the fit is
    \item
      One that penalizes complex models
    \end{itemize}
  \item
    WAIC uses the posterior distribution to estimate both terms
  \end{itemize}
\end{itemize}
\end{frame}

\subsubsection{Cross-Validation}\label{cross-validation}

\begin{frame}{Cross-Validation}
\protect\phantomsection\label{cross-validation-1}
\begin{itemize}
\tightlist
\item
  \textbf{\textcolor{red}{Cross-validation}} (CV)

  \begin{itemize}
  \tightlist
  \item
    \textbf{\textcolor{orange}{Procedure}}

    \begin{itemize}
    \tightlist
    \item
      Partition data into \(K\) portions of equal size and similar
      statistics
    \item
      Use \(K-1\) partitions to train the model and test on remaining
      partition
    \item
      Repeat for all \(K\) folds
    \item
      Average the results
    \end{itemize}
  \item
    \textbf{\textcolor{darkgreen}{Pros}}

    \begin{itemize}
    \tightlist
    \item
      Simple and effective solution to use all data to compare models
    \end{itemize}
  \end{itemize}
\item
  \textbf{\textcolor{teal}{Leave-one-out cross-validation}} (LOO-CV)

  \begin{itemize}
  \tightlist
  \item
    \textbf{\textcolor{cyan}{Procedure}}:

    \begin{itemize}
    \tightlist
    \item
      The model is fit for all data, excluding one observation
    \item
      The model's predictive accuracy is tested on the left out
      observation
    \item
      Repeat the process for all observations
    \item
      Average the results
    \end{itemize}
  \item
    \textbf{\textcolor{blue}{Cons}}

    \begin{itemize}
    \tightlist
    \item
      It is very computationally expensive since one needs to refit the
      model
    \end{itemize}
  \end{itemize}
\item
  How to adapt
  \textbf{\textcolor{violet}{cross-validation to a Bayesian approach}}?

  \begin{itemize}
  \tightlist
  \item
    CV and LOO require multiple model fits and fitting a Bayesian model
    is very expensive
  \item
    Yes! There is a way to approximate using a single fit to the data
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{ELPD with LOO-CV}
\protect\phantomsection\label{elpd-with-loo-cv}
\begin{itemize}
\tightlist
\item
  \includegraphics[width=0.14583in,height=\textheight,keepaspectratio]{assets/emoji/skull.png}
  Math alert
\item
  We want to compute \(ELPD_{LOO-CV}\) where:

  \begin{itemize}
  \tightlist
  \item
    ``Expected Log-Pointwise predictive Density'' (ELPD)

    \begin{itemize}
    \tightlist
    \item
      It should be ELPPD and not ELPD!
    \end{itemize}
  \item
    ``Leave-One-Out Cross-Validation'' (LOO-CV) is used to compute it
  \end{itemize}
\item
  The definition of ELPD with LOO-CV is: \begingroup \small
  $$
  ELPD_{LOO-CV} =
    \red{\sum_{i=1}^n} \log
    % Need to avoid the \textcolor{blue}{\texttt{text}} inside \textcolor{blue}{\texttt{\textcolor}}.
    \textcolor{violet}{\int}
    \teal{p(y_i | \theta)}
    \blue{p(\theta | y_{-i})}
    \textcolor{violet}{d\theta}
  $$
  \endgroup where:

  \begin{itemize}
  \tightlist
  \item
    \textcolor{blue}{Fit model using all the data without $y_{-i}$}
  \item
    \textcolor{teal}{Predict with the model the unseen $y_i$}
  \item
    \textcolor{violet}{\text{Integrate on all the posterior values}}
  \item
    \textcolor{red}{\text{Repeat for all the points}}
  \end{itemize}
\item
  How to compute it efficiently?

  \begin{itemize}
  \tightlist
  \item
    Use ``Pareto smooth importance sampling leave-one-out
    cross-validation''
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Pointwise Predictive Density (PPD)}
\protect\phantomsection\label{pointwise-predictive-density-ppd}
\begin{itemize}
\tightlist
\item
  The \textbf{pointwise predictive density} for a given data point
  \(y_i\) is defined as the posterior predictive probability, given the
  rest of the data \[
  PPD
  \defeq \Pr(y_i | data - \{i\})
  = \textcolor{blue}{\int} \red{p(y_i | \theta)} \green{p(\theta | y_{-i})} \textcolor{blue}{d\theta}
  \]

  \begin{itemize}
  \tightlist
  \item
    \(y_i\): observed data point
  \item
    \textcolor{red}{$p(y_i | \theta)$}:
    \textcolor{red}{\text{likelihood}} given model parameters \(\theta\)
  \item
    \textcolor{darkgreen}{$p(\theta | y_{-i})$}:
    \textcolor{darkgreen}{\text{posterior distribution}} of the model
    parameters given rest of data
  \item
    \textcolor{blue}{\text{Integral}}: averages over posterior
    distribution, capturing parameter uncertainty
  \end{itemize}
\item
  \textbf{\textcolor{black}{\text{Interpretation}}}

  \begin{itemize}
  \tightlist
  \item
    PPD measures model's predictive ability for \(y_i\) when trained on
    data excluding \(y_i\)
  \item
    Similar to cross-validation, using Bayesian parameter averaging over
    the model parameters
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Expected Log Pointwise Predictive Density}
\protect\phantomsection\label{expected-log-pointwise-predictive-density}
\begin{itemize}
\item
  The ELPD is the \textcolor{red}{\text{average}} over unseen points of
  the \textcolor{darkgreen}{\text{log}} \textcolor{blue}{\text{PPD}} \[
  ELPD
  \defeq \textcolor{red}{\sum_{i=1}^n} \textcolor{green}{\log}
  \textcolor{blue}{\int p(y_i | \theta_{-i}) p(\theta_{-i} | y_{-i}) d\theta}
  \]
\item
  \textbf{\textcolor{red}{\textcolor{black}{\text{Interpretation}}}}

  \begin{itemize}
  \tightlist
  \item
    It can be used to determine which model generalizes better to new
    data
  \item
    ELPD measures the predictive accuracy of a Bayesian model on unseen
    data
  \item
    Train on \(y_{-i}\), i.e., all data excluding \(y_i\)
  \item
    For each point \(y_i\) excluded from the training set, there is a
    new distribution of the params \(\theta_{-i}\)
  \item
    Test on \(y_i\)
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{PSIS-LOO-CV}
\protect\phantomsection\label{psis-loo-cv}
\begin{itemize}
\item
  Compute the Expected Log Pointwise Predictive Density (ELPD) using
  Leave-One-Out Cross-Validation (LOO-CV):

  \[
  ELPD_{LOO-CV} \defeq \sum_i \log \int p(y_i | \theta) p(\theta | y_{-i}) d\theta
  \]
\item
  \textbf{\textcolor{red}{Problem}}: Need to train N models, one for
  every data point
\item
  \textbf{\textcolor{darkgreen}{Solution}}:

  \begin{itemize}
  \tightlist
  \item
    Pareto-Smoothed Importance Sampling (PSIS) Leave-One-Out
    Cross-Validation (LOO-CV) estimates without refitting for every
    point
  \item
    \textbf{\textcolor{blue}{Importance sampling}}:

    \begin{itemize}
    \tightlist
    \item
      Use full dataset to approximate posterior distribution when one
      observation is left out
    \item
      Re-weight posterior samples based on importance
    \end{itemize}
  \item
    \textbf{\textcolor{violet}{Pareto-smoothing}}:

    \begin{itemize}
    \tightlist
    \item
      Stabilize importance weights, reducing extreme weights' impact
    \item
      E.g., if an observation left out influences the posterior
      distribution
    \item
      Provide diagnostics to assess reliability of importance weights
    \end{itemize}
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Bayesian Model Selection}
\protect\phantomsection\label{bayesian-model-selection}
\begin{itemize}
\tightlist
\item
  \textbf{\textcolor{red}{Bayesian way to compare $k$ models}}

  \begin{itemize}
  \tightlist
  \item
    Calculate the evidence of each model \(\Pr(Y | M_k)\), i.e., the
    probability of observed data \(Y\) given each model \(M_k\)
  \end{itemize}
\item
  Fitting a model and model selections are the same process in Bayesian
  approach

  \begin{itemize}
  \tightlist
  \item
    The VC framework considers fitting models and selecting models in
    the same way
  \item
    In the frequentist approach there are different procedures
  \end{itemize}
\item
  \textbf{\textcolor{darkgreen}{Model fitting}}

  \begin{itemize}
  \item
    Consider Bayes theorem for parameters \(\theta\) and data \(Y\),
    given model \(M_k\) \[
    \Pr(\theta | Y, M_k)
    = \frac{\Pr(Y | \theta, M_k) \Pr(\theta | M_k)}{\Pr(Y | M_k)}
    \]
  \item
    Find parameters \(\theta\) that maximize the ratio, independently of
    evidence probability \[
    \argmax_{\theta} \Pr(\theta | y, M_k)
    = \argmax_{\theta} \Pr(y|\theta, M_k) \Pr(\theta | M_k)
    \]
  \end{itemize}
\item
  \textbf{\textcolor{blue}{Model selection}}

  \begin{itemize}
  \tightlist
  \item
    To choose the best model among \(M_1, ..., M_k\), pick the one that
    maximizes \[
    \argmax_k \Pr(M_k | y) \propto \Pr(y | M_k) \Pr(M_k)
    \]
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Model Averaging}
\protect\phantomsection\label{model-averaging}
\begin{itemize}
\item
  What do you do when you have multiple models explaining the data?

  \begin{enumerate}
  \tightlist
  \item
    \textbf{\textcolor{red}{Model selection}}

    \begin{itemize}
    \tightlist
    \item
      Select one model
    \item
      Simple solution
    \end{itemize}
  \item
    \textbf{\textcolor{darkgreen}{Report all models with their informations}}

    \begin{itemize}
    \tightlist
    \item
      E.g., standard errors, posterior predictive checks
    \item
      Express advantages and shortcomings of the models
    \end{itemize}
  \item
    \textbf{\textcolor{blue}{Average all the models}}

    \begin{itemize}
    \tightlist
    \item
      Build a meta-model using a weighted average of each model
    \item
      Weight prediction by the difference between information criteria
      (e.g., WAIC, LOO) of the models
    \item
      A hierarchical model is a continuous versions of multiple discrete
      models
    \end{itemize}
  \end{enumerate}
\end{itemize}

\begin{frame}{Bayes Factors}
\protect\phantomsection\label{bayes-factors}
\begin{itemize}
\tightlist
\item
  \textbf{\textcolor{red}{Bayes factors}} are ratio of two marginal
  likelihoods of the data under competing model hypotheses \(M_0\) and
  \(M_1\) \[
  BF = \frac{\Pr(y|M_0)}{\Pr(y|M_1)}
  \] where \(BF > 1\) means model 0 explains data better than model 1
\end{itemize}

\begin{frame}{Assumption of Bayes Factors}
\protect\phantomsection\label{assumption-of-bayes-factors}
\begin{itemize}
\item
  The assumption of Bayes factor is that the models have the same prior
  probability
\item
  Otherwise we need to compute the ``posterior odds'' as ``Bayes
  factors'' x ``prior odds''

  \[
  \frac{\Pr(M_0 | y)}{\Pr(M_1 | y)}
  = \frac{\Pr(y | M_0)}{\Pr(y | M_1)} \frac{\Pr(M_0)}{\Pr(M_1)}
  = \text{Bayes factors} \times \text{prior odds}
  \]
\end{itemize}
\end{frame}

\begin{frame}{Bayes Factors: Pros and Cons}
\protect\phantomsection\label{bayes-factors-pros-and-cons}
\begin{itemize}
\item
  Looking at the definition of marginal likelihood (aka evidence):

  \[
  p(y) = \int_{\theta} p(y|\theta) p(\theta) d\theta
  \]
\item
  Making the dependency of the model \(M_k\) explicit

  \[
  p(y | M_k) = \int_{\theta_k} p(y|\theta_k, M_k) p(\theta_k, M_k) d\theta_k
  \]
\item
  Pros

  \begin{itemize}
  \tightlist
  \item
    Models with more parameters have a larger prior, so the Bayes factor
    has a built-in Occam's Razor
  \end{itemize}
\item
  Cons

  \begin{itemize}
  \tightlist
  \item
    The marginal likelihood needs to be computed numerically over a
    large dimensional space
  \item
    The marginal likelihood depends on the value of the prior

    \begin{itemize}
    \tightlist
    \item
      Changing the prior might not affect the inference of \(\theta\)
      but have a direct effect on the marginal likelihood
    \end{itemize}
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Hierarchical Models: Candies in a Jar Examples}
\protect\phantomsection\label{hierarchical-models-candies-in-a-jar-examples}
\begin{itemize}
\item
  Each classroom has a jar filled with candies, each different but
  coming from the same candy shop
\item
  Kids in each classroom need to guess the number of candies in each jar
\item
  Individual guesses

  \begin{itemize}
  \tightlist
  \item
    Think of each jar as its own little puzzle
  \item
    E.g., guess based on how big the jar is, how filled it is
  \item
    Each jar has certain ``parameters''
  \end{itemize}
\item
  Group learning

  \begin{itemize}
  \tightlist
  \item
    Consider what you learn from other jars since they come from the
    same candy shop
  \item
    E.g., the shop prefers to use a certain type of candies, or fills
    the jar up to a certain level
  \item
    The jars have certain ``hyper-parameters''
  \end{itemize}
\item
  Sharing info

  \begin{itemize}
  \tightlist
  \item
    As you make more guesses, you start sharing what you have learned
    with your friends about each jar
  \item
    The hierarchical model lets the info flow across models for
    individual jar
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Computing Bayes Factors as Hierarchical Models}
\protect\phantomsection\label{computing-bayes-factors-as-hierarchical-models}
\begin{itemize}
\item
  The computation of Bayes factors can be framed as a hierarchical model

  \begin{itemize}
  \tightlist
  \item
    The high-level parameter is an index assigned to each model and
    sampled from a categorical distribution
  \end{itemize}
\item
  We perform inference of the competing models at the same time, using a
  discrete variable jumping between models

  \begin{itemize}
  \tightlist
  \item
    The proportion we use to sample each model is proportional to
    \(\Pr(M_k | y)\)
  \end{itemize}
\item
  Then we compute the Bayes factors
\item
  The models can be different in the prior, in the likelihood, or both
\end{itemize}
\end{frame}

  sampling from it

  \item
    E.g., when model 0 is chosen, the parameters in model 1 are updated,
    but they are only restricted by the prior
  \item
    If the prior is too vague, the parameter values might be too far
    from previous accepted values and the step is rejected

\end{enumerate}

\begin{frame}{Priors and Regularization}
\protect\phantomsection\label{priors-and-regularization}
\begin{itemize}
\item
  Using weakly/informative priors is a way of pushing a model to prevent
  overfitting and generalize well
\item
  This is similar to the idea of ``regularization''
\item
  Regularization

  \begin{itemize}
  \tightlist
  \item
    Reduce information that a model can represent and reduce chances to
    capture noise instead of signal
  \item
    E.g., penalize large values for the parameters in a model
  \item
    E.g., ridge and Lasso regression applies regularization to least
    square method
  \end{itemize}
\end{itemize}
\end{frame}
