==== Machine Learning Explainability
<machine-learning-explainability>
- #text(fill: red, weight: "bold")[Question]: #emph["A model predicts a
  patient has 92% chance of heart disease $arrow.r$ should the doctor
  trust it?"]
  - Without explanation, even accurate models are unusable in
    high-stakes decisions
- #text(fill: green, weight: "bold")[Problem]: ML models are
  increasingly used for decisions that affect people's lives
  - E.g., credit scoring, medical diagnosis, criminal sentencing, hiring
  - Stakeholders (e.g., doctors, judges, regulators) need to understand
    #emph[why] a prediction was made, not just #emph[what] it is
- #text(fill: blue, weight: "bold")[Definition]: #emph[Explainability]
  is the degree to which a human can understand the cause of a model's
  decision
  - Aka "Interpretable ML", "XAI" (Explainable Artificial Intelligence)

==== Accuracy vs Interpretability
<accuracy-vs-interpretability>
- #text(fill: red, weight: "bold")[Key idea]: there is a fundamental
  tension between model #emph[accuracy] and #emph[interpretability]

- #text(fill: green, weight: "bold")[Example]:

  - Linear regression $arrow.r$ interpretable but limited capacity
  - Deep neural networks $arrow.r$ high capacity but opaque
    (#emph["black box"];)

- #text(fill: blue, weight: "bold")[Goal]: develop methods that

  - Explain black-box models #emph[post-hoc]
  - Without sacrificing predictive performance

<taxonomy-of-explainability-methods>
- Explainability methods can be classified along several axes

==== Local vs.~Global Explanations
<local-vs.-global-explanations>
- #text(fill: red, weight: "bold")[Local Explanations]: Explain a single
  prediction for a specific input
  - E.g., #emph["This loan was rejected because income $<$ \$30k and
    debt-to-income ratio $>$ 0.6"]
  - #emph[Methods];:
    - LIME, SHAP, Counterfactuals
  - #emph[Pros];:
    - Actionable for the individual affected
    - Required by regulations (e.g., GDPR "right to explanation")
- #text(fill: green, weight: "bold")[Global Explanations]: Explain the
  model's overall decision-making logic
  - E.g., #emph["Across all predictions, income and credit history are
    the two most important features"]
  - #emph[Methods];: feature importance, partial dependence plots,
    global surrogates
  - #emph[Pros];:
    - Help model developers debug and validate
    - Enable stakeholders to assess fairness across populations
- #text(fill: blue, weight: "bold")[Key idea]: local and global
  explanations are complementary
  - A complete picture requires both

==== Model-Agnostic vs.~Model-Specific Methods
<model-agnostic-vs.-model-specific-methods>
- #text(fill: red, weight: "bold")[Model-specific]:
  - Methods exploit the model's internal structure
    - Decision tree $arrow.r$ follow the path from root to leaf
    - Linear model $arrow.r$ read coefficients directly
    - Neural network $arrow.r$ gradient-based saliency maps, attention
      weights
  - #emph[Pros];: computationally efficient, structurally faithful
  - #emph[Cons];: tied to one model class, not transferable
- #text(fill: blue, weight: "bold")[Model-agnostic]
  - Methods treat the model as a black box $f : X arrow.r Y$
    - Only require input-output access $arrow.r$ query $f \( x \)$ and
      observe predictions
  - E.g., LIME, SHAP, permutation importance, partial dependence
  - #emph[Pros];: applicable to any model, comparable across models
  - #emph[Cons];: can be computationally expensive, may not capture
    internal mechanisms

==== Intrinsic Interpretability vs.~Post-Hoc Explanation
<intrinsic-interpretability-vs.-post-hoc-explanation>
- #text(fill: red, weight: "bold")[Definition]: #emph[intrinsically
  interpretable] models are understandable by design, without any
  additional explanation method
  - The model #emph[is] the explanation
  - E.g., decision trees, linear models
- #text(fill: green, weight: "bold")[Definition]: #emph[post-hoc]
  methods explain a model #emph[after] it has been trained
  - Applied to black-box models to extract understanding
- #text(fill: blue, weight: "bold")[Key idea]: the choice between
  intrinsic and post-hoc is a design decision

==== Linear and Generalized Additive Models (GAMs)
<linear-and-generalized-additive-models-gams>
- #text(fill: red, weight: "bold")[Key idea]: linear models explain
  predictions through #emph[additive feature contributions]
  - Each feature $x_j$ contributes $beta_j x_j$ to the prediction
  - Coefficient $beta_j$ quantifies feature $j$'s effect
- #text(fill: green, weight: "bold")[Definition]: a #emph[linear model]
  predicts:
  $ hat(y) = beta_0 + beta_1 x_1 + beta_2 x_2 + dots.h.c + beta_p x_p $
  - #text(fill: blue, weight: "bold")[Interpretation]: increasing $x_j$
    by one unit changes $hat(y)$ by $beta_j$, holding all else equal
- #text(fill: rgb("#8B00FF"), weight: "bold")[Definition]: a
  #emph[Generalized Additive Model] (GAM) extends to nonlinear features:
  $ hat(y) = beta_0 + f_1 \( x_1 \) + f_2 \( x_2 \) + dots.h.c + f_p \( x_p \) $
  - Each $f_j$ is a smooth, potentially nonlinear function (e.g.,
    spline)
  - #emph[Pros];: captures nonlinear patterns while remaining additive;
    each feature's effect can be plotted independently
  - #emph[Cons];: cannot capture feature interactions unless explicitly
    added as $f_(j k) \( x_j \, x_k \)$ terms

==== SHAP: Shapley Values Foundation
<shap-shapley-values-foundation>
- #text(fill: red, weight: "bold")[Key idea]: SHAP (Lundberg and Lee,
  2017) uses #emph[Shapley values] from cooperative game theory to
  fairly distribute the prediction among features

- #text(fill: blue, weight: "bold")[Definition]: the Shapley value
  $phi.alt_j$ for feature $j$ is:

  $ phi_j = sum_(S subset.eq N without {j}) ((|S|)! (|N| - |S| - 1)!) / (|N|)! (f(S union {j}) - f(S)) $
  where:

  - $N$ = set of all features
  - $S$ = a subset excluding feature $j$
  - $f \( S \)$ = model prediction using only features in $S$

- The sum averages the #emph[marginal contribution] of $j$ over all
  possible orderings

==== SHAP: Intuition and Example
<shap-intuition-and-example>
- #text(fill: red, weight: "bold")[Setup]
  - 3 friends #text(fill: blue)[`A`] (Alice), #text(fill: blue)[`B`]
    (Bob), #text(fill: blue)[`C`] (Carol) work together
  - They earn \$100k on a project
  - How do you split it fairly if each contributes differently?
- #text(fill: green, weight: "bold")[Problem]: contributions are
  "contextual", i.e., depend on order and who participates
  - #text(fill: blue)[`A`] alone earns \$40k
  - #text(fill: blue)[`A`] + #text(fill: blue)[`B`] together earn \$90k,
    #text(fill: blue)[`B`] adds \$50k when #text(fill: blue)[`A`] is
    there
  - #text(fill: blue)[`A`] + #text(fill: blue)[`B`] +
    #text(fill: blue)[`C`] earn \$100k, #text(fill: blue)[`C`] adds
    \$10k when both are there
  - But if #text(fill: blue)[`C`] came first, she might have contributed
    \$60k
- #text(fill: blue, weight: "bold")[Idea]
  - Try every possible order they could have joined
  - Compute each person's marginal contribution in that order
  - Average to compute the Shapley value of each person
- With 3 people there are 3! = 6 orderings:

#styled-table(
  ("Order", "A Contribution", "B Contribution", "C Contribution"),
  (
    ("A → B → C", "\$40k", "\$50k", "\$10k"),
    ("A → C → B", "\$40k", "\$45k", "\$15k"),
    ("B → A → C", "\$20k", "\$70k", "\$10k"),
    ("B → C → A", "\$10k", "\$80k", "\$10k"),
    ("C → A → B", "\$35k", "\$25k", "\$40k"),
    ("C → B → A", "\$10k", "\$50k", "\$40k"),
  )
)
- Then average to get the Shapley values

==== SHAP: ML Example
<shap-ml-example>
- #text(fill: red, weight: "bold")[Setup]: predicting house price with
  three features
  - Baseline (no features): \$200k
  - Predicted price: \$300k
  - Three features: Bedrooms ($B$), Location ($L$), Square footage ($S$)
- There are $3 ! = 6$ possible orderings; for each, compute marginal
  contribution:

#styled-table(
  ("Order", "B (Bedrooms)", "L (Location)", "S (Sq. Ft.)"),
  (
    ("B → L → S", "\$30k", "\$50k", "\$20k"),
    ("L → B → S", "\$35k", "\$40k", "\$25k"),
    ("B → S → L", "\$25k", "\$35k", "\$40k"),
    ("L → S → B", "\$40k", "\$35k", "\$25k"),
    ("S → B → L", "\$40k", "\$30k", "\$30k"),

  $2^p$ coalitions, not just orderings, but the intuition is identical

==== SHAP: Properties and Computation
<shap-properties-and-computation>
- #text(fill: red, weight: "bold")[Properties]:

  - SHAP satisfies desirable properties
  - #emph[Efficiency];: values sum to the prediction difference from
    baseline
  - #emph[Symmetry];: features with identical contributions get equal
    attribution
  - #emph[Dummy];: features that never change the prediction get
    $phi.alt_j = 0$
  - #emph[Additivity];: for ensemble models, SHAP values of the ensemble
    equal the average of individual SHAP values

- #text(fill: green, weight: "bold")[Problem]: exact computation
  requires $2^p$ model evaluations (exponential in the number of
  features)

- #text(fill: blue, weight: "bold")[Solution]: efficient approximations
  exist

  - #text(fill: blue)[`KernelSHAP`]: weighted regression approximation
    (model-agnostic)
  - #text(fill: blue)[`TreeSHAP`]: for tree-based models
  - #text(fill: blue)[`DeepSHAP`]: backpropagation-based for neural
    networks

==== SHAP: Visualization and Interpretation
<shap-visualization-and-interpretation>
- #text(fill: red, weight: "bold")[Key idea]: SHAP allows visualization
  for both local and global explanations

- #text(fill: green, weight: "bold")[Local explanation] (single
  prediction):

  - #emph[Force plot];: shows how each feature pushes the prediction

    $f \( x \)$
  - E.g., #emph["This house is priced \$50k above average because it has
    4 bedrooms (+\$30k) and is near a school (+\$20k)"]

- #text(fill: blue, weight: "bold")[Global explanation] (entire
  dataset):

  - E.g., #emph["Square footage and location are the two most important

  - #emph[Summary plot];: shows the distribution of SHAP values for each
    feature across all data points
  - #emph[Dependence plot];: shows how one feature's SHAP value varies
    with its actual value, revealing nonlinear effects

==== LIME: Local Interpretable Model-agnostic Explanations
<lime-local-interpretable-model-agnostic-explanations>
- #text(fill: red, weight: "bold")[Key idea]: approximate a complex
  model #emph[locally] with a simple, interpretable model (Ribeiro et
  al., 2016)

#grid(
  columns: (55%, 45%),
  gutter: 0.5em,
  [
  - #text(fill: green, weight: "bold")[Algorithm]:
    + Pick an instance $x$ to explain
    + Generate perturbed samples ${ z_1 \, . . . \, z_N }$ around $x$
    + Weight each $z_i$ by proximity to $x$ using a kernel
      $pi_x \( z_i \)$
    + Query the black-box model $f \( \)$ on all $z_i$ to get predictions
      $f \( z_i \)$
    + Fit a simple model $g$ (e.g., linear) on
      ${ \( z_i \, f \( z_i \) \) }$ weighted by $pi_x$
  - #text(fill: blue, weight: "bold")[Example]: a spam classifier flags an
    email
    - LIME reveals the words #text(fill: blue)[`"free"`],
      #text(fill: blue)[`"winner"`], and #text(fill: blue)[`"click here"`]
      drove the prediction
    - The linear explanation assigns a positive coefficient to each of
      these tokens
  ],

==== LIME: Formal Objective
<lime-formal-objective>
- #text(fill: red, weight: "bold")[Definition]: LIME finds the best
  local explanation by solving:

  $ g^* = op("arg min")_(g in G) sum_(i=1)^N pi_x(z_i) (f(z_i) - g(z_i))^2 + Omega(g) $
  where:

  - $f \( \)$ is the function to explain
  - $G$ is restricted to a class of inherently interpretable models
    $g \( \)$
  - $z_i$ are perturbed samples around the point to interpret $x$
  - $pi_x \( z_i \)$ is the locality kernel
    $exp \( - frac(D \( x \, z_i \)^2, sigma^2) \)$
  - $Omega \( g \)$ penalizes complexity of the explanation (e.g.,
    number of non-zero coefficients)

- #text(fill: green, weight: "bold")[Interpretation]: LIME minimizes
  weighted reconstruction error between the black-box $f \( \)$ and the
  simple surrogate $g \( \)$, with more weight on samples close to $x$

- #text(fill: blue, weight: "bold")[Intuition]: The locality kernel
  ensures that $g \( \)$ is is fit to faithfully match $f \( \)$
  behavior near $x$ while being allowed to disagree with $f \( \)$ far
  away

  - $D \( \)$ is the distance function
  - $sigma$ is a width parameter (hyperparameter to choose)
  - Samples $z_i$ close to $x$ get weight near 1; samples far away get
    weight near 0

==== LIME: Limitations
<lime-limitations>
- LIME solves

  $ g^* = op("arg min")_(g in G) sum_(i=1)^N pi_x(z_i) (f(z_i) - g(z_i))^2 + Omega(g) $

- Explanations depend on the perturbation strategy

  - Different perturbations can yield different explanations
    $exp \( - frac(D \( x \, z_i \)^2, sigma^2) \)$

- The kernel width is a hyperparameter that affects locality

  - No theoretical guarantees on faithfulness to the original model

<lime-detecting-broken-model>
- #text(fill: red, weight: "bold")[Goal]: classify 20 newsgroups text as

  - 94% held-out accuracy suggests high trust
- #text(fill: blue, weight: "bold")[Problem]: LIME reveals that
  predictions are made for arbitrary reasons
  - Classifier learned to use email headers and author names, which
    would not generalize
  - Words #text(fill: blue)[`Posting`], #text(fill: blue)[`Host`],
    #text(fill: blue)[`Re`] appear important but have no connection to
    Christianity or Atheism
  - E.g., #text(fill: blue)[`Posting`] appears in 22% of training

  - These issues are invisible from raw data or held-out accuracy alone
  - Remediation: remove leaked features, retrain

==== Permutation Feature Importance
<permutation-feature-importance>
- #text(fill: red, weight: "bold")[Key idea]: measure how much the
  model's performance #emph[degrades] when a feature's values are
  randomly shuffled (Breiman, 2001)

- #text(fill: green, weight: "bold")[Algorithm]:

  + Compute baseline performance $P_0$ on the validation set
  + For each feature $j$:
    - Randomly permute the values of $x_j$ across all samples

    - Compute the new performance $P_j$

    - Importance of feature $j$:

      $ phi_j = P_0 - P_j $
  + Repeat and average over multiple permutations for stability

- #text(fill: blue, weight: "bold")[Interpretation]: a large drop
  $phi.alt_j$ means the model relies heavily on feature $j$

==== Permutation Feature Importance: Pros and Cons
<permutation-feature-importance-pros-and-cons>

  - Model-agnostic, global, easy to implement
  - Directly tied to predictive performance
- #text(fill: blue, weight: "bold")[Cons]:
  - Breaks feature correlations $arrow.r$ can produce unrealistic data
    points
  - Correlated features split importance (e.g., height and weight)
  - Only measures #emph[predictive] importance, not #emph[causal]
    importance

==== Counterfactual Explanations
<counterfactual-explanations>
- #text(fill: red, weight: "bold")[Definition]: A #emph[counterfactual
  explanation] identifies the smallest change to input to flip the
  model's decision (Wachter et al., 2017)

- #text(fill: green, weight: "bold")[Example]: Loan application denied

  - Counterfactual: #emph["If your income were \$5k higher and you had
    no outstanding defaults, the loan would be approved"]
  - Tells the applicant what to change, not just why it was rejected

- #text(fill: blue, weight: "bold")[Key idea]: Counterfactuals are
  #emph[actionable] and suggest a path from current to desired outcome

- #text(fill: rgb("#8B00FF"), weight: "bold")[Properties]:

  - #emph[Proximity];: Close to original input
  - #emph[Sparsity];: Change few features
  - #emph[Plausibility];: Realistic counterfactual
  - #emph[Actionability];: Change features user can control
    - E.g., age and race are immutable

==== Counterfactual Explanations: Formal Framework
<counterfactual-explanations-formal-framework>
- #text(fill: red, weight: "bold")[Definition]: find a counterfactual
  $x'$ by solving:

  $ x' = op("arg min")_(x') d(x, x') quad "subject to" quad f(x') = y' $
  - $x$ = original input
  - $y'$ = desired outcome
  - $d \( dot.op \, dot.op \)$ = distance function measuring how much
    the input changes

- #text(fill: green, weight: "bold")[Remark]: in practice, a soft
  constraint formulation is used:

  $ x' = op("arg min")_(x') (lambda dot.op ell(f(x'), y') + d(x, x')) $
  - $ell$ is a loss penalizing predictions far from $y'$
  - $lambda$ controls the tradeoff between achieving $y'$ and staying
    close to $x$

- #text(fill: blue, weight: "bold")[Limitations]:

  - Multiple valid counterfactuals may exist
  - Counterfactuals may lie outside the data manifold (unrealistic)
  - Sensitive to the choice of distance metric $d$

==== Explainability in Bayesian Models
<explainability-in-bayesian-models>
- #text(fill: red, weight: "bold")[Key idea]: Bayesian models provide a
  natural form of explainability through #emph[uncertainty
  quantification]

  - Instead of a single point prediction, they output a full posterior
    distribution over outcomes

- #text(fill: green, weight: "bold")[Intuition]: a model that says
  #emph["I predict 80% chance of disease, but I'm very uncertain"] is
  more informative than one that just says #emph["disease"]

- #text(fill: blue, weight: "bold")[Definition]: in Bayesian inference,
  we update our belief about parameters $theta$ given data $cal(D)$:

  $ Pr(theta | cal(D)) = frac(Pr(cal(D) | theta) dot.op Pr(theta), Pr(cal(D))) $
  where

  - the numerator is "likelihood × prior"
  - denominator is "evidence"

==== Credible Intervals
<credible-intervals>
- #text(fill: red, weight: "bold")[Key idea]: the shape of the posterior
  distribution directly communicates model uncertainty about each
  parameter

- #text(fill: orange, weight: "bold")[Definition]: a #emph[credible
  interval] \[$theta_L$, $theta_U$\] contains the true parameter with
  probability $1 - alpha$:

  $ Pr(theta_L lt.eq theta lt.eq theta_U | cal(D)) = 1 - alpha $

- #text(fill: green, weight: "bold")[Interpretation]:

  - #emph[Narrow] posterior: model is confident about θ
  - #emph[Wide] posterior: high uncertainty, need more data
  - #emph[Multimodal] posterior: multiple plausible explanations exist

- #text(fill: teal, weight: "bold")[Example]: predicting treatment
  effect

  - Posterior mean = 5.2 units
  - 95% credible interval = \[1.1, 9.3\]
  - #emph["The treatment likely has a positive effect, but we're
    uncertain about its magnitude"]

- #text(fill: rgb("#00FFFF"), weight: "bold")[Remark]: credible
  intervals have a probability interpretation, unlike frequentist
  confidence intervals

==== Uncertainty Quantification as a Form of Explanation
<uncertainty-quantification-as-a-form-of-explanation>
- #text(fill: red, weight: "bold")[Key idea]: knowing #emph[what the
  model doesn't know] is an explanation

- #text(fill: green, weight: "bold")[Definition]: two types of
  uncertainty

  - #emph[Aleatoric] (data uncertainty): irreducible noise in the data
    - E.g., inherent randomness in patient outcomes
  - #emph[Epistemic] (model uncertainty): reducible with more data
    - E.g., model hasn't seen enough examples of a rare condition

- #text(fill: blue, weight: "bold")[Interpretation]: a Bayesian model
  decomposes uncertainty (using Law of Total Variance)

  $ bb(V) [Y | x, cal(D)] = bb(E) [bb(V) [Y | x, theta]] + bb(V) [bb(E) [Y | x, theta]] $
  where:

  - The first term is aleatoric (data) uncertainty
  - The second is epistemic (model) uncertainty

- #text(fill: rgb("#8B00FF"), weight: "bold")[Example]: a medical
  diagnosis model

  - High aleatoric uncertainty: #emph["This case is inherently
    ambiguous"]
  - High epistemic uncertainty: #emph["We haven't seen enough cases like
    this, collect more data"]

==== Causal AI and Explainability
<causal-ai-and-explainability>
- #text(fill: red, weight: "bold")[Problem]: most ML explanations are
  #emph[correlational]

  - #emph["feature $X$ is associated with outcome $Y$"] does not mean
    #emph["$X$ causes $Y$"]

- #text(fill: green, weight: "bold")[Question]: #emph["Does the model's
  explanation reflect a true causal mechanism, or just a spurious
  correlation in the training data?"]

- #text(fill: blue, weight: "bold")[Key idea]: causal AI provides tools
  to distinguish #emph[why] something happens from #emph[what] co-occurs

  - Pearl's #emph[Ladder of Causation] (2018):
    + #emph[Association] (seeing): $P r \( Y \| X \)$ $arrow.r$
      observational
    + #emph[Intervention] (doing): $P r \( Y \| d o \( X \) \)$
      $arrow.r$ experimental
    + #emph[Counterfactual] (imagining):
      $P r \( Y_x \| X = x' \, Y = y' \)$ $arrow.r$ retrospective

- #text(fill: rgb("#8B00FF"), weight: "bold")[Remark]:

  - Standard ML operates at level 1 (association)
  - Causal explanations require level 2 or 3

==== Counterfactual Reasoning in Causal Frameworks
<counterfactual-reasoning-in-causal-frameworks>
- #text(fill: red, weight: "bold")[Key idea]: causal counterfactuals
  differ from predictive counterfactuals
  - Predictive counterfactuals: #emph["Given observations, what's the
    best guess about an outcome under different conditions?"]
  - Causal counterfactuals: #emph["What would have happened to this
    individual if I had intervened and changed one thing?"]
- #text(fill: green, weight: "bold")[Definition]: causal counterfactual
  #emph["$Y$ had $X$ been $x$"] for an individual with observed
  $\( X = x' \, Y = y' \)$ is computed in three steps:
  + \_Abduction\_infer exogenous variables $U$ from observations
    {=typst} \$ Pr(U | X = x' , Y = y') \$
  + #emph[Action];: modify structural equation for $X$ to
    $d o \( X = x \)$
  + #emph[Prediction];: compute counterfactual outcome $Y_x$ under
    modified model with inferred $U$
- #text(fill: blue, weight: "bold")[Example]: a patient received
  treatment A and recovered
  - Counterfactual: #emph["Would the patient have recovered with
    treatment B?"]
  - Requires full SCM, not just observational data
- #text(fill: rgb("#8B00FF"), weight: "bold")[Remark]: causal
  counterfactuals are more demanding than interventional queries since
  require individual-level reasoning

<distinguishing-causal-explanations-from-feature-attribution>
- #text(fill: red, weight: "bold")[Problem]: feature attribution methods
  (SHAP, LIME) answer #emph["what features are important for the model's
  prediction?"] but not #emph["what features actually cause the
  outcome?"]

==== Quality of Explanations
<quality-of-explanations>
- Evaluating explanation quality requires checking:
  + #emph[Faithfulness];: does it reflect the model?
  + #emph[Stability];: is it consistent across similar inputs?
  + #emph[Robustness];: can it be gamed or manipulated?

==== Faithfulness of Explanations
<faithfulness-of-explanations>
- #text(fill: red, weight: "bold")[Definition]: an explanation is
  #emph[faithful] if it accurately reflects the model's actual reasoning
  process
  - A faithful explanation describes #emph[how the model truly works];,
    not just a plausible story
- #text(fill: green, weight: "bold")[Problem]: post-hoc explanations are
  approximations and may not accurately represent the model's internal
  logic
  - LIME's linear surrogate may miss nonlinear interactions
  - SHAP with marginal expectations may attribute importance to features
    the model never uses conditionally
- #text(fill: blue, weight: "bold")[Example]: testing faithfulness
  - Remove the top-$k$ features according to the explanation
  - If the prediction doesn't change $arrow.r$ the explanation is
    unfaithful
  - If it changes dramatically $arrow.r$ the explanation is likely
    faithful

==== Stability and Robustness of Explanations
<stability-and-robustness-of-explanations>
- #text(fill: red, weight: "bold")[Definition]: an explanation is
  #emph[stable] if small changes to the input produce small changes in
  the explanation
  - Aka #emph["continuity"] or #emph["smoothness"]
- #text(fill: green, weight: "bold")[Problem]: many explanation methods
  are #emph[unstable]
  - LIME: different random perturbations yield different explanations
    for the same input
  - Gradient-based methods: explanations can be noisy and visually
    incoherent
- #text(fill: blue, weight: "bold")[Definition]: an explanation is
  #emph[robust] if it cannot be manipulated by adversarial perturbations
  - Slack et al.~(2020): showed that biased models can be made to
    produce #emph[fair-looking] LIME/SHAP explanations via adversarial
    scaffolding
- #text(fill: rgb("#8B00FF"), weight: "bold")[Key idea]: unreliable
  explanations are worse than no explanations
  - They create false confidence in flawed models
  - Stakeholders make decisions based on explanations they trust

==== The Accuracy-Interpretability Tradeoff
<the-accuracy-interpretability-tradeoff>
- #text(fill: red, weight: "bold")[Key idea]: the
  #emph[accuracy-interpretability tradeoff] is the central tension in
  explainable ML

- #text(fill: orange, weight: "bold")[Intuition]: as models grow more
  complex, they capture more patterns in the data (higher accuracy) but
  become harder to understand

- #text(fill: green, weight: "bold")[Spectrum]:
