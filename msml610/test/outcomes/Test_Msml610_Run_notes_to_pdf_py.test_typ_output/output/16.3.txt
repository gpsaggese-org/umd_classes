==== Prompting: Language Models as Text Predictors
<prompting-language-models-as-text-predictors>
- #text(fill: red, weight: "bold")[Definition]: a #emph[pretrained
  language model] is a function trained to predict the next token given
  a context $ Pr \( x_t divides x_1 \, dots.h \, x_(t - 1) \) $

- #text(fill: green, weight: "bold")[Goal]: get useful behavior purely
  by shaping the input text (the #emph[prompt];)

  - No fine-tuning, no external tools, no loop
  - E.g., prompting GPT-style models with #emph["Translate to French:
    …"] to elicit translation without task-specific training

- #text(fill: blue, weight: "bold")[Limitation]:

  - The model can only produce text
  - Cannot check or act on what it produces

==== In-Context Learning
<in-context-learning>
- #text(fill: red, weight: "bold")[Definition]: #emph[in-context
  learning] is the ability to learn a task from a few examples placed in
  the prompt, without updating weights
  - It is the first emergent capability
- #text(fill: green, weight: "bold")[Example] (few-shot):
  - Show 3 input-output pairs, then a 4th input \/\/ TODO(ai\_gp): Add
    example of prompt
  - The model completes the pattern by analogy
- #text(fill: blue, weight: "bold")[Key idea]: the prompt became a
  #emph[programming interface]
  - Behavior is specified by demonstrations, not code
  - This made rapid task adaptation possible and set the stage for agent
    scaffolding
- #text(fill: rgb("#8B00FF"), weight: "bold")[Remark]: in-context
  learning is what lets us later describe #emph[tools] to a model purely
  in text

==== Chain-of-Thought: Reasoning in Text
<chain-of-thought-reasoning-in-text>
- #text(fill: red, weight: "bold")[Problem]: on multi-step problems
  (e.g., arithmetic, logic), models that output an answer directly are
  often wrong

- #text(fill: orange, weight: "bold")[Solution]: #emph[chain-of-thought]
  (CoT) prompting asks the model to generate intermediate reasoning
  steps before the final answer

  ```
  prompt> Let's think step by step
  ```

- #text(fill: green, weight: "bold")[Example]:

  - Question: a word problem with several quantities \/\/ TODO(ai\_gp):
    Add example
  - CoT: the model writes out each arithmetic step, then the answer

- #text(fill: teal, weight: "bold")[Key idea]: reasoning can be
  externalized as text, giving the model more #emph[serial computation]
  before committing to an answer

- #text(fill: rgb("#00FFFF"), weight: "bold")[Limitation]: CoT reasons
  about the world but never #emph[checks] its claims against it

==== Acting on the World
<acting-on-the-world>
- #text(fill: red, weight: "bold")[Problem]: pure text generation, even
  with reasoning, is a closed loop

  - The model cannot retrieve a fact it does not know
  - It cannot verify an intermediate result
  - It cannot change anything outside the conversation

- #text(fill: green, weight: "bold")[Example]: asked #emph["what is the
  current population of Tokyo?"];, a reasoning-only model can only
  recall stale training data, not look it up

- #text(fill: blue, weight: "bold")[Question]: what if the model could
  #emph[pause] its reasoning, take an action in the world, and resume
  with the result?

==== From Prompting to Acting
<from-prompting-to-acting>
- #text(fill: red, weight: "bold")[Key idea]: the field moved from
  treating the LLM as an #emph[oracle] to treating it as a
  #emph[controller]

==== ReAct: Motivation
<react-motivation>
- #text(fill: red, weight: "bold")[Problem]: two families of methods
  each had a critical weakness

  - #emph[Reasoning-only] (CoT): rich internal reasoning, but no
    grounding, so errors and hallucinations go unchecked
  - #emph[Action-only];: can call tools, but acts without explaining
    why, making behavior brittle and hard to debug

- #text(fill: green, weight: "bold")[Question]: can reasoning and acting
  be combined so each fixes the other's weakness?

- #text(fill: blue, weight: "bold")[Solution]: #emph[ReAct] (Reasoning +
  Acting) (Yao et al., 2022) prompts the model to alternate between:

  - #text(fill: blue)[`Thought`]: a reasoning step in natural language
  - #text(fill: blue)[`Action`]: a tool call chosen based on that
    thought
  - #text(fill: blue)[`Observation`]: the environment's response, fed
    back into context

- #text(fill: rgb("#8B00FF"), weight: "bold")[Key idea]:

  - Reasoning decides #emph[what to do]
  - Acting produces #emph[new evidence] to reason over next
  - This is exactly the perceive-plan-act loop, expressed as a text
    trace the model both reads and writes

==== ReAct: The Thought-Action-Observation Trace
<react-the-thought-action-observation-trace>
#box(image("/msml610/test/outcomes/Test_Msml610_Run_notes_to_pdf_py.test_typ_output/tmp.scratch/lesson_16.3/tmp.notes_to_pdf.preprocess_notes.txt.figs/tmp.notes_to_pdf.render_image.2.png"))

- #text(fill: red, weight: "bold")[Interpretation]:
  - The #text(fill: blue)[`Thought`] makes the agent's plan explicit and
    inspectable
  - The #text(fill: blue)[`Observation`] grounds the next
    #text(fill: blue)[`Thought`] in what actually happened
  - The cycle repeats until the agent emits a
    #text(fill: blue)[`Finish`] action

==== ReAct: Worked Example
<react-worked-example>
- #text(fill: red, weight: "bold")[Problem]: answer #emph["who wrote the
  novel that inspired the film that won Best Picture in year Y?"] using
  a search tool

- #text(fill: green, weight: "bold")[Solution] (ReAct trace):

  - #text(fill: blue)[`Thought`]: #emph["First find the Best Picture
    winner of year Y"]
  - #text(fill: blue)[`Action`]:
    #text(fill: blue)[`search("Best Picture year Y")`]
  - #text(fill: blue)[`Observation`]: #emph["Film F won"]
  - #text(fill: blue)[`Thought`]: #emph["Now find the novel that
    inspired F"]
  - #text(fill: blue)[`Action`]:
    #text(fill: blue)[`search("novel that inspired F")`]
  - #text(fill: blue)[`Observation`]: #emph["Novel N by author A"]
  - #text(fill: blue)[`Thought`]: #emph["The answer is A"] $arrow.r$
    #text(fill: blue)[`Finish(A)`]

- #text(fill: blue, weight: "bold")[Key idea]:

  - No single step needs to know the full chain
  - Each step is grounded by the previous observation

==== ReAct vs.~Chain-of-Thought vs.~Act-Only
<react-vs.-chain-of-thought-vs.-act-only>
#styled-table(
  headers: ("Method", "Reasons?", "Acts?", "Weakness"),
  rows: (
    ("Act-only", "No", "Yes", "No explanation, brittle"),
    ("Chain-of-Thought", "Yes", "No", "Ungrounded, hallucinates"),
    ("ReAct", "Yes", "Yes", "More tokens, tool latency"),
  ),
)
- #text(fill: red, weight: "bold")[Key idea]: ReAct dominates on
  knowledge-intensive tasks because #emph[grounding] suppresses
  hallucination while #emph[reasoning] guides the search

- #text(fill: blue, weight: "bold")[Remark]:

  - ReAct is not the most token-efficient method
  - But it is far more #emph[reliable] on tasks requiring external facts

==== Why ReAct Worked
<why-react-worked>
- #text(fill: red, weight: "bold")[Intuition]: interleaving creates a
  #emph[virtuous cycle]
  - Reasoning reduces wasted actions by planning the next step
  - Observations reduce hallucination by injecting real evidence
- #text(fill: green, weight: "bold")[Pros]:
  - Traces are human-readable and debuggable
  - Recovers from errors: a bad observation triggers a corrective
    thought
  - Requires no fine-tuning, only prompting
- #text(fill: blue, weight: "bold")[Cons]:
  - Depends on a reliable tool interface and parseable action format
  - Long traces consume context window quickly
- #text(fill: rgb("#8B00FF"), weight: "bold")[Key idea]: ReAct is the
  template most modern agent frameworks still follow

==== Early Failures: Overview
<early-failures-overview>
- There are recurring ways early LLM agents broke
  - Understand failure modes
  - Explain the design of modern safeguards
- #text(fill: red, weight: "bold")[Dominant failure modes]:
  + Compounding errors over long horizons
  + Hallucinated or malformed tool calls
  + Getting stuck in repetitive loops
  + Brittle output parsing and grounding
- #text(fill: blue, weight: "bold")[Key takeaways] distilled from early
  failures:
  - Detect and recover from errors instead of assuming per-step
    correctness
  - Prefer #emph[typed, validated] actions over free-form text
  - Always bound the loop with a step budget and stopping condition
  - Give the agent memory of what it already tried
  - Keep traces inspectable so failures can be diagnosed

==== Failure: Compounding Errors
<failure-compounding-errors>
- #text(fill: red, weight: "bold")[Problem]: in a multi-step task, a
  small early mistake propagates
  - E.g., if agent misreads the goal, every later step builds on the
    error
  - With per-step success probability $p$ and $n$ independent steps,
    end-to-end success scales like $p^(thin n)$
    - E.g., even $p = 0.95$ gives only $approx 0.60$ over $10$ steps
- #text(fill: blue, weight: "bold")[Lesson]: long-horizon reliability
  needs error #emph[detection] and #emph[recovery];, not just high
  per-step accuracy

==== Failure: Hallucinated Tool Calls
<failure-hallucinated-tool-calls>
- #text(fill: red, weight: "bold")[Problem]: the agent invents a tool
  that does not exist or supplies arguments in the wrong format
  - E.g., calling #text(fill: blue)[`book_flight()`] when only
    #text(fill: blue)[`search_flight()`] is available
  - E.g., passing a date as prose instead of ISO format
- #text(fill: green, weight: "bold")[Cons]:
  - The environment rejects the call, wasting a step
  - Worse, a loosely validated runtime may execute an unintended action
- #text(fill: blue, weight: "bold")[Lesson]: constrain outputs with
  typed schemas and validate every call before execution

==== Failure: Getting Stuck in Loops
<failure-getting-stuck-in-loops>
- #text(fill: red, weight: "bold")[Problem]: without memory of what it
  already tried, an agent repeats the same failing action, e.g.,

- #text(fill: green, weight: "bold")[Example]: a web agent that

  - Keeps searching the exact same query, observing the same empty
    result, and searching again
  - Clicks the same broken link again and again

- #text(fill: blue, weight: "bold")[Lesson]: agents need a stopping
  condition, a step budget, and short-term memory of recent actions and
  observations

==== Failure: Brittle Parsing and Grounding
<failure-brittle-parsing-and-grounding>
- #text(fill: red, weight: "bold")[Problem]: early agents emitted
  actions as free-form text, parsed with regular expressions, which
  breaks whenever the model rephrases its output

- #text(fill: green, weight: "bold")[Solution]: structured output (e.g.,
  JSON matching a schema) plus a fixed, finite action space

  - The environment, not the model's prose, determines the effect

- #text(fill: blue, weight: "bold")[Lesson]: grounding must be
  #emph[enforced] by the runtime, not merely requested in the prompt

==== From Narrow to General-Purpose Agents
<from-narrow-to-general-purpose-agents>
- #text(fill: red, weight: "bold")[Definition]: a #emph[general-purpose
  agent] can operate across many task types and environments with the
  same core architecture
  - Contrast with a #emph[narrow agent] built for one benchmark (e.g.,
    WebShop only)
- #text(fill: green, weight: "bold")[Key idea]: the perceive-plan-act
  loop is #emph[environment-agnostic]
  - Swap the tools and observation format, keep the controller
  - The same ReAct-style loop drives web, coding, and OS agents
- #text(fill: blue, weight: "bold")[Ingredients of General-Purpose Agents]
  + A capable base LLM (reasoning + instruction following)
  + A standardized #emph[tool interface] (typed schemas, function
    calling)
  + A control loop with memory and error recovery
  + An environment that exposes observations and a finite action space

==== The Rise of Tool-Use Standards
<the-rise-of-tool-use-standards>
- #text(fill: red, weight: "bold")[Problem]: every early agent invented
  its own ad-hoc action format, preventing reuse across projects

- #text(fill: green, weight: "bold")[Solution]: standardized
  #emph[function calling] / tool schemas described once as
  #text(fill: blue)[`(name, typed parameters, description)`]

  - The model emits a structured call the runtime validates and executes

- #text(fill: blue, weight: "bold")[Key idea]: standardizing the tool
  interface decoupled the #emph[agent logic] from the #emph[specific
  tools]

  - New capabilities are added by registering new tools, not rewriting
    the agent

==== Scaling Meets Agents
<scaling-meets-agents>
- #text(fill: red, weight: "bold")[Observation]: as base models scaled,
  agentic behavior improved
  - Better instruction following $arrow.r$ fewer malformed actions
  - Longer context windows $arrow.r$ longer, more coherent traces
  - Stronger reasoning $arrow.r$ better planning within the loop
- #text(fill: blue, weight: "bold")[Remark]: many early failures were
  partly
  - #emph[capability] failures that scaling alleviated (better models);
    and
  - #emph[design] failures that scaffolding fixed (better loops)
  - Progress came from both fronts at once

==== Open Challenges on the Road Ahead
<open-challenges-on-the-road-ahead>
- #text(fill: red, weight: "bold")[Limitations] still open after this
  early history:
  - Reliability over very long horizons (compounding errors persist)
  - Verifying agent actions before they take effect
  - Memory that persists across sessions, not just within a loop
  - Safety when the action space touches the real world
- #text(fill: blue, weight: "bold")[Key idea]:
  - #emph[How to act] is solved
  - The frontier is #emph[how to act reliably and safely]

==== A Brief History of LLM Agents: Summary
<a-brief-history-of-llm-agents-summary>
- #text(fill: red, weight: "bold")[Key takeaways]:
  - The field moved from #emph[prompting] an oracle to running an LLM as
    a #emph[controller] in a loop
  - In-context learning and chain-of-thought supplied adaptation and
    reasoning, but no grounding
  - #emph[ReAct] fused reasoning and acting, interleaving
    #text(fill: blue)[`Thought`], #text(fill: blue)[`Action`], and
    #text(fill: blue)[`Observation`] into one grounded trace
  - #emph[WebShop] showed language was not the bottleneck; robust
    multi-step navigation was
  - Early failures (compounding errors, hallucinated calls, loops,
    brittle parsing) taught the design principles behind modern agents
  - General-purpose agents emerged by holding the loop fixed and
    standardizing the tool interface
- #text(fill: blue, weight: "bold")[Open questions]:
  - How do reasoning, memory, and planning combine to fix long-horizon
    reliability?
  - How do we evaluate and trust these agents before deployment?
