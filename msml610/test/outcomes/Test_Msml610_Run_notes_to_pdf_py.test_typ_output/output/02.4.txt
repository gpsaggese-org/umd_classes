// Styled table with zebra striping, lateral lines, and configurable width.
#let styled-table(headers: (), rows: (), caption: none, col-widths: none, bold-first-col: true, size: 0.8em, width: 80%) = {
  let n = headers.len()
  let widths = if col-widths != none { col-widths } else { (1fr,) * n }

  // Zebra striping: alternate white and darker gray backgrounds on full rows
  let processed-rows = rows.enumerate().map(((idx, row)) => {
    let bg-color = if calc.rem(idx, 2) == 0 { white } else { rgb("#e8e8e8") }
    if bold-first-col {
      (
        table.cell(fill: bg-color, text(fill: black, weight: "bold", row.at(0))),
        ..row.slice(1).map(cell => table.cell(fill: bg-color, text(fill: rgb("#555555"), cell)))
      )
    } else {
      row.map(cell => table.cell(fill: bg-color, text(fill: rgb("#555555"), cell)))
    }
  })

  text(size: size,
    figure(
      align(center,
        block(width: width,
          table(
            columns: widths,
            align: (left,) * n,
            stroke: none,
            table.vline(x: 0, stroke: 2pt),
            table.hline(stroke: 2pt),
            table.header(
              ..headers.map(h => table.cell(fill: black, text(fill: white, weight: "bold", h)))
            ),
            table.hline(stroke: 1.5pt),
            ..processed-rows.flatten(),
            table.hline(stroke: 2pt),
            table.vline(x: n, stroke: 2pt),
          )
        )
      ),
      kind: table,
      caption: caption,
    )
  )
}

<gradient-descent-intuition>
#grid(

  - #text(fill: black, weight: "bold")[Solution];:
    - At each point:
      - You look around
      - You move a step in the direction where the surface is steepest

  - #text(fill: black, weight: "bold")[Gradient descent]
    - Is a general technique for minimizing twice-differentiable functions

==== Gradient descent with fixed learning rate (1/3)
<gradient-descent-with-fixed-learning-rate-13>
- Consider the contour plot of a function

- #text(fill: black, weight: "bold")[Start] from a point $bold(underline(w)) \( 0 \)$ (random, the
  origin, …)

- #text(fill: black, weight: "bold")[At each step]

  - Move a fixed amount $eta$ in weight space (fixed learning rate):
    $ bold(underline(w)) \( t + 1 \) = bold(underline(w)) \( t \) + eta hat(bold(underline(v))) $
    where $hat(bold(underline(v)))$ is a unit vector

  - Pick $hat(bold(underline(v)))$ to move to a value of
    $E_(i n) \( bold(underline(w)) \)$ as negative as possible

- The #text(fill: black, weight: "bold")[change for $E_(i n)$] is:

  - Gradient descent keeps only $O \( eta \)$ the term and ignores the
    rest
  - Conjugate gradient considers up to $O \( eta^2 \)$ and ignores
    higher infinitesimals

==== Gradient Descent with Fixed Learning Rate (2/3)
<gradient-descent-with-fixed-learning-rate-23>
- You have:
  $ Delta E_(i n) approx eta nabla E_(i n) \( bold(underline(w)) \( t \) \)^T hat(bold(underline(v))) $

- The #text(fill: black, weight: "bold")[minimal value of the scalar product] $Delta E_(i n)$:

  - Happens when
    $hat(bold(underline(v))) = - frac(nabla E_(i n) \( bold(underline(w)) \( t \) \), parallel nabla E_(i n) \( bold(underline(w)) \( t \) \) parallel)$
  - Is
    $- eta parallel nabla E_(i n) \( bold(underline(w)) \( t \) \) parallel$

- The #text(fill: black, weight: "bold")[change in weights] $Delta bold(underline(w))$ is:

- Called #text(fill: black, weight: "bold")["gradient descent"] since it descends along the
  gradient of the function to optimize

==== Gradient Descent with Fixed Learning Rate (3/3)
<gradient-descent-with-fixed-learning-rate-33>
- Each $j$ component of the weight $bold(underline(w))$ is updated with
  the partial derivative with respect to that coordinate:
  - The update of all components should be #text(fill: black, weight: "bold")[simultaneous];, i.e.,
    computed at once
- A step of the optimization when we update the solution (weights) is
  called #text(fill: black, weight: "bold")[epoch]

==== Gradient Descent: Stopping Criteria
<gradient-descent-stopping-criteria>
- #text(fill: black, weight: "bold")[In theory];, stop when $Delta E_(i n) = bold(underline(0))$
  - Numerically, this might not occur
- #text(fill: black, weight: "bold")[In practice];, stop when:
  - Variation of $E_(i n)$ is smaller than threshold
    $Delta E_(i n) < theta$
  - Reached a certain number of iterations
- #text(fill: black, weight: "bold")[Monitoring gradient descent]
  - In theory, only compute derivatives of function
    $J \( bold(underline(w)) \)$ to optimize
  - In practice, monitor progress by recomputing cost function
    $J \( bold(underline(w)) \)$ periodically to ensure it decreases

==== Gradient Descent with Fixed Learning Rate
<gradient-descent-with-fixed-learning-rate>
- Consider a 1D convex function
  - If #text(fill: black, weight: "bold")[$eta$ is too small];:
    - Linear approximation of $E_(i n)$ is effective
    - Many steps needed to converge to minimum
  - If #text(fill: black, weight: "bold")[$eta$ is too large];:
    - Linear approximation fails (higher terms affect values)
    - It "bounces around"

#box(image("/msml610/lectures_source/figures/L02.4.Gradient_descent_3.png", width: 90.0%))

- #text(fill: black, weight: "bold")[Idea];: vary learning rate $eta$ during gradient descent
  - Smaller learning rates may find a better minimum
  - Reduce $eta$ as a function of iterations
  - #text(fill: black, weight: "bold")[Cons];: introduces an additional parameter to tune

==== Gradient Descent with Variable Learning Rate
<gradient-descent-with-variable-learning-rate>
- In #text(fill: black, weight: "bold")[gradient descent with fixed learning rate] (constant change
  in weight space), use:
  $ Delta bold(underline(w)) = - eta frac(nabla J, parallel nabla J parallel) $

- #text(fill: black, weight: "bold")[To converge quickly:]

  - Move fast (large change) in weight space (large $eta$) when surface
    is steep (large gradient)
  - Move slow (small change) in weight space (small $eta$) near minimum
    to avoid bouncing (small gradient)
  - Ideally, $eta$ should increase with slope:
    $eta prop parallel nabla J parallel$

- #text(fill: black, weight: "bold")[Gradient descent with variable learning rate];:
  $ Delta bold(underline(w)) = - eta nabla J $

==== Feature Scaling in Gradient Descent
<feature-scaling-in-gradient-descent>
- #text(fill: black, weight: "bold")[Problem];: Different gradient components have different errors
  due to numerical approximation, causing bouncing
  - Unscaled features lead to slow, unstable convergence
  - E.g., feature ranging from 1 to 1000 vs.~0.01 to 1 causes
    inefficient updates
- #text(fill: black, weight: "bold")[Solution];: Converge faster by scaling features to the same
  range
  - Min-max scaling
  - Standardization (transforms feature values to mean 0, standard
    deviation 1)

==== Issues with Batch Gradient Descent
<issues-with-batch-gradient-descent>
- Consider squared error with $n$ samples:
  $ E_(i n) \( bold(underline(w)) \) eq.delta 1 / n sum_(i = 1)^n \( h_(bold(underline(w))) \( bold(underline(x))_i \) - y_i \)^2 $

- #text(fill: black, weight: "bold")[Batch Gradient Descent (BGD)] updates each weight component:
  $ bold(underline(w)) \( t + 1 \) = bold(underline(w)) \( t \) - eta frac(nabla E_(i n), parallel nabla E_(i n) parallel) $

  - Coordinate update for squared error:
    $ w_j \( t + 1 \) = w_j \( t \) - eta 2 / n sum_(i = 1)^n \( h_(bold(underline(w))) \( bold(underline(x))_i \) - y_i \) frac(partial h_(bold(underline(w))) \( bold(underline(x))_i \), partial w_j) $

  - #text(fill: black, weight: "bold")[Cons];: gradient descent with many training examples (e.g.,
    $N = 10^6$)

    - Is computationally expensive, requiring gradient evaluation from
      all examples for one update
    - Requires storing all data in memory

<stochastic-gradient-descent>
==== Stochastic Gradient Descent
<stochastic-gradient-descent-1>
- Idea of #text(fill: black, weight: "bold")[Stochastic Gradient Descent (SGD)];: update the
  weights only for one training example picked at random

- #text(fill: black, weight: "bold")[Algorithm]

  - Pick one $\( bold(underline(x))_n \, y_n \)$ at a time from the
    available examples
  - Compute $nabla e \( h \( bold(underline(x))_n \) \, y_n \)$ to
    update the weights: $Delta bold(underline(w)) = - eta nabla e$
  - Update the weight considering only one random example:
    $ w_j \( t + 1 \) = w_j \( t \) - eta 2 / n \( h_(bold(underline(w))) \( bold(underline(x))_t \) - y_t \) frac(partial h_(bold(underline(w))) \( bold(underline(x))_t \), partial w_j) $

- #text(fill: black, weight: "bold")[Cons];: in Stochastic Gradient Descent

  - Path in weight space is random
  - Oscillates around local minimum

- #text(fill: black, weight: "bold")[Why SGD works]

  - $nabla e$ is a function of a random var $bold(underline(x))_n$
  - The average direction of SGD is the same direction as batch version
    $ bb(E) \[ nabla e \] = 1 / N sum nabla e \( h \( bold(underline(x))_n \) \, y_n \) = nabla 1 / N sum e \( h \( bold(underline(x))_n \) \, y_n \) = nabla E_(i n) $

==== Mini-Batch Gradient Descent
<mini-batch-gradient-descent>
- #text(fill: black, weight: "bold")[Mini-Batch Gradient Descent] brings together characteristics
  of both Batch and Stochastic Gradient Descent
  - Use $b$ examples to make an update to the current weight
  - $b$ represents the batch size
  - A common choice is $b = 32$ or $b = 64$
- Mini-batch GD offers a balance between SGD noisiness and full-batch
  approaches, using small, random data samples for updates

==== Coordinate Descend
<coordinate-descend>
- #text(fill: black, weight: "bold")[Idea];: minimize $J \( x_0 \, . . . \, x_n \)$ by optimizing
  along one direction $x_i$ at a time
  - Instead of computing all derivatives
- #text(fill: black, weight: "bold")[Algorithm]
  - Pick a random starting point $bold(underline(w)) \( 0 \)$
  - Pick a random order for the coordinates ${ x_i }$
  - Find the minimum along the current coordinate (1D optimization
    problem)
  - Move to the next coordinate $x_(i + 1)$
  - The sequence of $bold(underline(w)) \( t \)$ is decreasing
  - A minimum is found if there is no improvement after one cycle of
    scanning all coordinates
  - The minimum is local

==== Gradient Descent vs Pseudo-Inverse
<gradient-descent-vs-pseudo-inverse>
- For linear models, you can use pseudo-inverse or gradient descent to
  find optimal $bold(underline(w))^(\*)$

- #text(fill: black, weight: "bold")[Gradient descent]

  - Choose learning rate $eta$
  - Requires many iterations
  - Monitor stopping criteria, oscillations
  - Effective for many features $P$

- #text(fill: black, weight: "bold")[Pseudo-inverse]

  - No parameter selection
  - Converges in one iteration
  - Computes a $P times P$ matrix
    $\( bold(underline(underline(X)))^T bold(underline(underline(X))) \)^(- 1)$
    - Complexity of matrix inversion $O \( P^3 \)$
    - For $P approx 10 \, 000$, prefer gradient descent
