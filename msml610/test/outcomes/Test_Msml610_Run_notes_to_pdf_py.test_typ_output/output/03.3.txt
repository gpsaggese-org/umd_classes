// Styled table with zebra striping, lateral lines, and configurable width.
#let styled-table(headers: (), rows: (), caption: none, col-widths: none, bold-first-col: true, size: 0.8em, width: 80%) = {
  let n = headers.len()
  let widths = if col-widths != none { col-widths } else { (1fr,) * n }

  // Zebra striping: alternate white and darker gray backgrounds on full rows
  let processed-rows = rows.enumerate().map(((idx, row)) => {
    let bg-color = if calc.rem(idx, 2) == 0 { white } else { rgb("#e8e8e8") }
    if bold-first-col {
      (
        table.cell(fill: bg-color, text(fill: black, weight: "bold", row.at(0))),
        ..row.slice(1).map(cell => table.cell(fill: bg-color, text(fill: rgb("#555555"), cell)))
      )
    } else {
      row.map(cell => table.cell(fill: bg-color, text(fill: rgb("#555555"), cell)))
    }
  })

  text(size: size,
    figure(
      align(center,
        block(width: width,
          table(
            columns: widths,
            align: (left,) * n,
            stroke: none,
            table.vline(x: 0, stroke: 2pt),
            table.hline(stroke: 2pt),
            table.header(
              ..headers.map(h => table.cell(fill: black, text(fill: white, weight: "bold", h)))
            ),
            table.hline(stroke: 1.5pt),
            ..processed-rows.flatten(),
            table.hline(stroke: 2pt),
            table.vline(x: n, stroke: 2pt),
          )
        )
      ),
      kind: table,
      caption: caption,
    )
  )
}

==== Motivation
<motivation>
- Distinction
  - Ontological commitment: what exists in the world
  - Epistemological commitment: what an agent believes about facts

==== Ontological Commitment
<ontological-commitment>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Ontological
  commitments] are assumptions about reality made by a language
  - Different formal models make different assumptions on how truth is
    defined
- #text(fill: blue, weight: "bold")[Examples]:
  - #emph[Propositional logic];: world consists of facts that are either
    true or false
    - E.g., $P or Q$
  - #emph[First-order logic];: world consists of objects with relations
    that hold or do not hold
    - E.g.,
      $forall x : H u m a n \( x \) arrow.r.double.long M o r t a l \( x \)$
  - #emph[Higher-order logic];: relations can be objects themselves
    - E.g., assertions about relations like #emph["all relations are
      transitive"]
  - #emph[Temporal logic];: facts hold at particular times or intervals
    \\/\/ TODO(ai\_gp): Add example

==== Epistemological Commitment
<epistemological-commitment>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Epistemological
  commitment] is the possible states of knowledge an agent holds with
  respect to each fact

- #text(fill: blue, weight: "bold")[Examples]

  - #emph[Propositional];, #emph[first-order logic];: 3 possible states
    of belief (true, false, unknown)
  - #emph[Probability theory];: each sentence has a degree of belief in
    \[0, 1\]
    - E.g., $Pr \( X = 6 \) = 0.3$

==== Non-monotonic Logic
<non-monotonic-logic>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Non-monotonic
  logic] is a logic where adding new information can invalidate previous
  conclusions

- #text(fill: green, weight: "bold")[Comparison]:

  - #emph[Classical logic];: once proven, conclusions remain true even
    with new information
  - #emph[Non-monotonic logic];: conclusions change as new facts are
    learned

- #text(fill: blue, weight: "bold")[Example]

  - Initial KB: #emph["Birds typically fly"];, #emph["Tweety is a bird"]
  - Conclusion: #emph["Tweety can fly"]
  - New fact: #emph["Tweety is a penguin"] and #emph["penguins cannot
    fly"]
  - Revised conclusion: #emph["Tweety cannot fly"]

- #text(fill: rgb("#8B00FF"), weight: "bold")[Intuition]:

  - Real-world reasoning involves incomplete or evolving knowledge
  - Non-monotonic logic allows systems to reason flexibly and adapt to
    new circumstances

==== Default Reasoning
<default-reasoning>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Default
  reasoning] makes assumptions by default in the absence of contrary
  evidence, allowing conclusions based on typical situations unless
  exceptions are found

- #text(fill: green, weight: "bold")[Key idea]:

  - Assume the most likely case unless specified otherwise
  - If new information contradicts the assumption, revise the conclusion

- #text(fill: blue, weight: "bold")[Example]

  - Default rule: #emph["Typically, birds can fly"]
  - Fact: #emph["Tweety is a bird"]
  - Conclusion: #emph["Tweety can fly"]
  - New fact: #emph["Tweety is a penguin"]
  - Revised: #emph["Tweety cannot fly"]

- #text(fill: rgb("#8B00FF"), weight: "bold")[Pros]: allows systems to
  function reasonably without complete information

- #text(fill: black, weight: "bold")[Initial facts]
  - $A l i c e$ is a $S t u d e n t$
  - $A l i c e$ belongs to the $C o m p u t e r S c i e n c e$
    department
  - $C S 101$ is a $C o u r s e$ offered by the
    $C o m p u t e r S c i e n c e$ department
- #text(fill: black, weight: "bold")[Default rule];:
  - Each $S t u d e n t$ in the $C o m p u t e r S c i e n c e$
    department takes all classes in their department
- #text(fill: black, weight: "bold")[Initial reasoning]
  - Since $A l i c e$ is a $S t u d e n t$ in
    $C o m p u t e r S c i e n c e$, by default $S t u d e n t s$ take
    $C S 101$
  - Conclusion: $t a k e s C o u r s e \( A l i c e \, C S 101 \)$
- #text(fill: black, weight: "bold")[New information]
  - $A l i c e$ is a student who does not meet the prerequisites for
    $C S 101$
- #text(fill: black, weight: "bold")[Revised reasoning]
  - New conclusion:
    $not t a k e s C o u r s e \( A l i c e \, C S 101 \)$

==== Common Sense Reasoning
<common-sense-reasoning>
- #text(fill: red, weight: "bold")[Problem]: Typical knowledge is often
  implicit and taken by granted by humans

  - #emph["If you drop a glass, it will likely break"]
  - #emph["People eat food when hungry"]

- #text(fill: orange, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Common sense
  reasoning] makes assumptions and draws conclusions based on everyday
  knowledge about the world

- #text(fill: green, weight: "bold")[Characteristics]

  - Deals with incomplete, uncertain, ambiguous information
  - Relies on defaults, heuristics, and typical patterns, not strict
    proofs
  - Flexible and tolerant of exceptions

- #text(fill: teal, weight: "bold")[Challenges]

  - Knowledge is vast, informal, imprecisely defined
  - Difficult to encode in machine-readable form
  - Handling exceptions and contradictions is complex

- #text(fill: rgb("#00FFFF"), weight: "bold")[Techniques]

  - Knowledge graphs, non-monotonic logic, probabilistic reasoning,
    machine learning

==== Open World vs Closed World Assumptions
<open-world-vs-closed-world-assumptions>
- #text(fill: red, weight: "bold")[Definition]: the #text(fill: black, weight: "bold")[Closed World
  Assumption (CWA)] implies that any missing information is false by
  default
  - E.g., in relational databases (SQL), logic programming, business
    rules
- #text(fill: green, weight: "bold")[Example]:
  - Fact: #emph["Alice takes CS101"]
  - Nothing said about Bob
  - CWA conclusion: #emph["Bob does not take CS101"]
- #text(fill: blue, weight: "bold")[Definition]: the #text(fill: black, weight: "bold")[Open World
  Assumption (OWA)] implies that any missing information is unknown, not
  false
  - E.g., semantic Web (RDF, OWL), incomplete or growing data
- #text(fill: rgb("#8B00FF"), weight: "bold")[Example]:
  - Fact: #emph["Alice takes CS101"] is known
  - Nothing said about Bob
  - OWA conclusion: #emph["Bob's enrollment is unknown"]

==== Inductive Logic Programming
<inductive-logic-programming>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Inductive logic
  programming] learns logical rules from examples and background
  knowledge
  - Given positive/negative examples and background facts, infer rules
    that explain them
- #text(fill: green, weight: "bold")[Example]
  - Background knowledge: #emph["Birds have wings"]
  - Positive: #emph["Tweety is a bird that can fly"]
  - Negative: #emph["Penguin cannot fly"]
  - Learned rule: #emph["Birds can fly unless they are penguins"]
- #text(fill: blue, weight: "bold")[Pros]:
  - Produces human-readable rules
  - Integrates learning with symbolic reasoning
  - Supports background knowledge
- #text(fill: rgb("#8B00FF"), weight: "bold")[Challenges]:
  - Computational complexity with large datasets
  - Can Handle noisy, incomplete data

==== Description Logic
<description-logic>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Description
  logic] represents structured knowledge about a domain
  - Balances expressivity and computational efficiency
  - More expressive than propositional logic, less than first-order
    logic
- #text(fill: green, weight: "bold")[Components]
  - #emph[Classes];: abstract groups (e.g., $P e r s o n$,
    $A n i m a l$)
  - #emph[Properties];: binary relations (e.g., $h a s C h i l d$,
    $o w n s P e t$)
  - #emph[Instances];: specific objects (e.g., $G P$, GP's dog
    $N u v o l o$)
- #text(fill: black, weight: "bold")[Reasoning tasks]
  - Concept subsumption: #emph["Is class $A$ a subset of class $B$?"]
  - Instance checking: #emph["Does instance $a$ belong to class $A$?"]
- #text(fill: black, weight: "bold")[Syntax];: combines atomic concepts and roles with logical
  constructors ($sect.sq$, $union.sq$, $not$, $forall$, $exists$)
  - E.g.,
    $F a t h e r equiv M a n sect.sq exists h a s C h i l d . P e r s o n$
- #text(fill: blue, weight: "bold")[Examples]
  - Used widely in ontologies (e.g., OWL)

==== ALC
<alc>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Attributive
  Concept Language with Complements (ALC)] is a basic but expressive
  description logic

- Combines logical operators

  - $sect.sq$ (and), $union.sq$ (or), $not$ (not)
  - Existential and universal quantification: $exists R . C$,
    $forall R . C$
  - Set-theoretic interpretation (e.g., classes as sets, properties as
    binary relations)

- #text(fill: green, weight: "bold")[Example]

  - #emph["All students take some course"];:
    $upright("Student") equiv exists upright("takes") . upright("Course")$
  - #emph["A mother is a woman with at least one child"];:
    $upright("Mother") equiv upright("Woman") sect.sq exists upright("hasChild") . top$

- #text(fill: blue, weight: "bold")[Properties]

  - Decidable
  - Balances expressiveness and computational complexity
  - Foundation for more complex logics in OWL

==== SHOIN
<shoin>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[SHOIN] is a
  description logic more expressive than ALC

- #text(fill: green, weight: "bold")[Components]:

  - $cal(S)$: transitive properties
    - E.g., $a n c e s t o r O f$
  - $cal(H)$: role hierarchies
    - E.g., $h a s S o n subset.eq.sq h a s C h i l d$
  - $cal(O)$: specific individuals
    - E.g., $J o h n$ is nominal
  - $cal(I)$: inverse roles
    - E.g., $i s C h i l d O f$ inverse of $h a s C h i l d$
  - $cal(N)$: cardinality constraints
    - E.g., #emph["exactly 1 child"]

- #text(fill: blue, weight: "bold")[Example]: #emph["exactly two
  children"];:
  $P e r s o n subset.eq.sq \( = 2 med h a s C h i l d . top \)$

- #text(fill: rgb("#8B00FF"), weight: "bold")[Pros]

  - More powerful, but reasoning harder (exponential complexity)
  - Models richer real-world scenarios
  - Foundation for OWL DL reasoning

==== OWL
<owl>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Web Ontology
  Language (OWL)]

  - Is a semantic web language representing complex knowledge about
    things and relationships
  - Enables rich knowledge representation on the web (based on SHOIN)
  - Supports formal semantics for machine reasoning

- #text(fill: orange, weight: "bold")[Components]: classes, properties,
  individuals, axioms

- #text(fill: green, weight: "bold")[Example]: #emph["Every cat is a
  mammal"];: $C a t subset.eq.sq M a m m a l$

- #text(fill: teal, weight: "bold")[Variants]:

  - #emph[OWL Lite];: simpler, for classification hierarchies
  - #emph[OWL DL];: full expressiveness with decidable reasoning
  - #emph[OWL Full];: maximum expressiveness, undecidable

- #text(fill: rgb("#00FFFF"), weight: "bold")[Applications]: semantic
  search, biomedical data

==== SPARQL
<sparql>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[SPARQL]

  - Is the query language for RDF data
  - Allows retrieval and manipulation of data stored in RDF format

- #text(fill: green, weight: "bold")[Components]

  - #emph[Triple Patterns];: query fragments matching triples in RDF
    graph
  - #emph[Basic Graph Pattern];: set of triple patterns
  - #emph[Variables];: stand in for unknown parts (e.g.,
    #text(fill: blue)[?person], #text(fill: blue)[?animal])

- #text(fill: black, weight: "bold")[Main query types]

  - #text(fill: blue)[SELECT]: retrieve specific variables
  - #text(fill: blue)[CONSTRUCT]: create new RDF triples from results
  - #text(fill: blue)[ASK]: boolean indicating if pattern exists
  - #text(fill: blue)[DESCRIBE]: return RDF graph describing resources

- #text(fill: blue, weight: "bold")[Example]: #emph["Find all resources
  of type Bird"]

  ```
  SELECT ?animal WHERE { ?animal rdf:type ex:Bird }
  ```

==== Semantic Web
<semantic-web>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[Semantic Web]

  - Extends the Web by enabling machines to understand and interpret
    data
  - Adds meaning/semantics to enable better integration, automation,
    discovery

- #text(fill: green, weight: "bold")[Problem]: HTML is human-readable
  but lacks semantic structure for computers

- #text(fill: blue, weight: "bold")[Components]:

  - RDF: base data model
  - SPARQL: query language for RDF
  - OWL: define rich ontologies

- Current status:

  - Core ideas (structured data, ontologies) widely adopted
  - Full vision partially realized

- #text(fill: rgb("#8B00FF"), weight: "bold")[Challenges]:

  - Widespread adoption complexity
  - Privacy
  - Data ownership
  - Standardization needs
  - Scalability
  - Centralization
  - Censorship

==== WikiData
<wikidata>
- #text(fill: red, weight: "bold")[Definition]: #text(fill: black, weight: "bold")[WikiData] is a
  free, open, collaborative knowledge base storing structured data for
  Wikipedia
  - Accessible via SPARQL APIs
  - Graph-based data model
- #text(fill: green, weight: "bold")[Components]:
  - #emph[Item];: entity or concept
    - E.g., #text(fill: blue)[Q42] = Douglas Adams
  - #emph[Property];: relationship or attribute
    - E.g., #text(fill: blue)[P31] = instance of, #text(fill: blue)[P27]
      \= country
  - #emph[Value];: specific data via property link
    - #text(fill: blue)[Q42] $arrow.r$ #text(fill: blue)[P31] $arrow.r$
