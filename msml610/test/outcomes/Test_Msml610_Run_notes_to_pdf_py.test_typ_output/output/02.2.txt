// Styled table with zebra striping, lateral lines, and configurable width.
#let styled-table(headers: (), rows: (), caption: none, col-widths: none, bold-first-col: true, size: 0.8em, width: 80%) = {
  let n = headers.len()
  let widths = if col-widths != none { col-widths } else { (1fr,) * n }

  // Zebra striping: alternate white and darker gray backgrounds on full rows
  let processed-rows = rows.enumerate().map(((idx, row)) => {
    let bg-color = if calc.rem(idx, 2) == 0 { white } else { rgb("#e8e8e8") }
    if bold-first-col {
      (
        table.cell(fill: bg-color, text(fill: black, weight: "bold", row.at(0))),
        ..row.slice(1).map(cell => table.cell(fill: bg-color, text(fill: rgb("#555555"), cell)))
      )
    } else {
      row.map(cell => table.cell(fill: bg-color, text(fill: rgb("#555555"), cell)))
    }
  })

  text(size: size,
    figure(
      align(center,
        block(width: width,
          table(
            columns: widths,
            align: (left,) * n,
            stroke: none,
            table.vline(x: 0, stroke: 2pt),
            table.hline(stroke: 2pt),
            table.header(
              ..headers.map(h => table.cell(fill: black, text(fill: white, weight: "bold", h)))
            ),
            table.hline(stroke: 1.5pt),
            ..processed-rows.flatten(),
            table.hline(stroke: 2pt),
            table.vline(x: n, stroke: 2pt),
          )
        )
      ),
      kind: table,
      caption: caption,
    )
  )
}

==== Machine Learning Paradigms with Examples (1/3)
<machine-learning-paradigms-with-examples-13>
- #text(fill: black, weight: "bold")[Supervised Learning]
  - Learn from labeled data to predict labels for new inputs
  - E.g., image classification using ResNet on ImageNet
- #text(fill: black, weight: "bold")[Unsupervised Learning]
  - Discover hidden patterns or structure in unlabeled data
  - E.g., K-means clustering for customer segmentation
- #text(fill: black, weight: "bold")[Reinforcement Learning]
  - Learn through interaction with an environment, receiving
    rewards/punishments
  - E.g., deep Q-Learning for playing Atari games
- #text(fill: black, weight: "bold")[Self-Supervised Learning]
  - Generate pseudo-labels from unlabeled data to pre-train models
  - E.g., BERT (Masked Language Modeling)
- #text(fill: black, weight: "bold")[Semi-Supervised Learning]
  - Combine small labeled data with large unlabeled data to improve
    performance
  - E.g., named entity recognition (NER) using annotated sentences with
    entity tags combined with many raw text documents

==== Machine Learning Paradigms with Examples (2/3)
<machine-learning-paradigms-with-examples-23>
- #text(fill: black, weight: "bold")[Online Learning]
  - Learn incrementally from a stream of data in real time
  - E.g., online logistic regression for click-through rate prediction
- #text(fill: black, weight: "bold")[Multi-Task Learning]
  - Train simultaneously a model to perform multiple related tasks
  - E.g., learn sentiment analysis and question answering
- #text(fill: black, weight: "bold")[Meta-Learning]
  - "Learning to learn": adapt quickly to new tasks using prior
    experience
  - E.g., a model can be fine-tuned quickly on a new task using just a
    few gradient steps
- #text(fill: black, weight: "bold")[Zero-Shot / Few-Shot Learning]
  - Generalize to new tasks with no or few labeled examples
  - E.g., GPT-4 solving tasks with zero-shot prompting
- #text(fill: black, weight: "bold")[Active Learning]
  - The model selects the most informative samples to be labeled by an
    oracle (e.g., a human)
  - E.g., pick samples where the model is least confident to get more
    examples

==== Machine Learning Paradigms with Examples (3/3)
<machine-learning-paradigms-with-examples-33>
- #text(fill: black, weight: "bold")[Federated Learning]
  - Train models across decentralized devices without sharing raw data
  - E.g., fraud detection or credit scoring across banks
- #text(fill: black, weight: "bold")[Evolutionary Learning]
  - Optimize model structures or parameters using evolutionary
    algorithms inspired by natural selection and genetics
  - Gradient free, global search, variable length inputs
  - E.g., genetic algorithms
- #text(fill: black, weight: "bold")[Curriculum Learning]
  - Train models on easier tasks first, gradually increasing difficulty
  - E.g., training in robotic control simulations
- #text(fill: black, weight: "bold")[Multi-Agent Learning]
  - Multiple agents learn and interact in shared environments, often in
    game-theoretic settings (e.g., competition, collaboration)
  - E.g., AlphaStar to play StarCraft II

==== Supervised Learning
<supervised-learning>
- Learn a function $f : X arrow.r Y$ that maps inputs to correct outputs
  - Training examples $\( bold(underline(x)) \, y \)$ with pairs of
    inputs and correct outputs
  - Requires labeled data for training
  - Measure performance with error on a separate test set
- #text(fill: black, weight: "bold")[Classification];: output is a discrete label, e.g.,
  - #text(fill: blue)[Spam] vs #text(fill: blue)[Not Spam]
  - Digit recognition #text(fill: blue)[0], #text(fill: blue)[1], …
  - Sentiment analysis #text(fill: blue)[Pos], #text(fill: blue)[Neg],
    #text(fill: blue)[Neutral]
- #text(fill: black, weight: "bold")[Regression];: output is a continuous value, e.g.,
  - House prices given features like size and location
  - House demand
  - Stock prices
- #text(fill: black, weight: "bold")[Common algorithms];:
  - Linear Regression
  - Decision Trees
  - K-nearest neighbors
  - Neural Networks
  - …

==== Unsupervised Learning
<unsupervised-learning>
- Learn from data #text(fill: black, weight: "bold")[without] labeled outputs
  - Goal: discover patterns or structure in the data
  - No explicit feedback signal
  - Evaluation can be qualitative
- #text(fill: black, weight: "bold")[Main techniques];:
  - #text(fill: black, weight: "bold")[Clustering];: Group similar examples, e.g.,
    - Customer segmentation
    - Grouping news articles by topic without knowing the topics
  - #text(fill: black, weight: "bold")[Dimensionality Reduction];: Reduce number of variables with
    PCA while preserving structure
    - E.g., visualize high-dimensional data in 2D
  - #text(fill: black, weight: "bold")[Density Estimation];: Estimate probability distribution of
    data
    - E.g., anomaly detection in server logs
  - #text(fill: black, weight: "bold")[Association Rule Learning];: Discover interesting relations
    between variables
    - E.g., market basket analysis (e.g., "people who buy X also buy Y")
- #text(fill: black, weight: "bold")[Common algorithms:]
  - K-means
  - PCA
  - Autoencoders

==== Reinforcement Learning
<reinforcement-learning>
- Learn by #text(fill: black, weight: "bold")[interacting with an environment] to #text(fill: black, weight: "bold")[maximize
  cumulative reward]
  - Learn policy $pi \( s \) arrow.r a$ that maximizes expected reward
  - Trade-off between exploration (trying new actions) and exploitation
    (using known good actions)
  - Environments provide clear rules and feedback (win/loss/reward)
  - Often involve physical simulation or real-world interaction

==== Question
<question>
- #text(fill: black, weight: "bold")[Make the question concrete and precise]
  - Define the problem clearly
  - Specify inputs and expected outputs
  - Align question with business or research objectives
  - E.g.,:
    - #text(fill: black, weight: "bold")[Bad];: #emph["How can we improve sales?"]
    - #text(fill: black, weight: "bold")[Good];: #emph["What factors most significantly impact
      sales of product X in region Y during season Z?"]
- Formulating question is #text(fill: black, weight: "bold")[the most important part] of the
  machine learning problem
  - Misunderstanding leads to:
    - Solving the wrong problem
    - Collecting wrong data
    - …
- #emph["If I were given one hour to save the planet, I would spend 59
  minutes defining the problem and one minute resolving it"] (Einstein)

==== Input Data
<input-data>
- Ensure #text(fill: black, weight: "bold")[data is specific to prediction] goal
  - E.g., use known movie ratings to predict unseen movie ratings from
    the same population
  - Training set $approx$ test set
- Relationship between data and prediction goal is #text(fill: black, weight: "bold")[not always
  direct]
  - E.g., interested in prices but predict supply and demand instead
- Poor-quality data leads to inaccurate predictions
  - #emph["Garbage in - garbage out"]
- Recognize #text(fill: black, weight: "bold")[when data is insufficient] for valid answers
  - #emph["Combination of data and desire for an answer does not ensure
    a reasonable answer can be extracted"] (John Tukey)
- #text(fill: black, weight: "bold")[More data vs better models]
  - Meta-studies show difference between generic and best model is like
    5%
  - #emph["It's not who has the best algorithm that wins. It's who has
    the most data"] (Google researcher)
  - #emph["Every time I fire a linguist, the performance of the speech
    recognizer goes up"] (IBM researcher in speech recognition)

==== Features
<features>
- #text(fill: black, weight: "bold")[Features] provide high-level information about inputs
  - E.g., use intensity and symmetry for scanned numbers instead of raw
    bit maps
- #text(fill: black, weight: "bold")[Characteristics of good features];:
  + Perform data compression
  + Retain relevant information
  + Often created with expert knowledge
- #text(fill: black, weight: "bold")[Common mistakes in feature building];:
  + Automating feature selection may lead to overfitting
    - Black box predictions can be accurate but stop working anytime
    - E.g., Google Flu's unclear feature-model link
  + Ignoring data-specific quirks
    - E.g., mislabeling outliers
  + Unnecessarily discarding information

==== Models
<models>
- Best models are:
  - #text(fill: black, weight: "bold")[Interpretable]
    - Allow users to understand and trust the model's decisions
    - E.g., decision trees are appropriate in medical studies since they
      produce a "reasoning"
  - #text(fill: black, weight: "bold")[Simple]
    - Easier to implement and maintain
    - Reduces the risk of overfitting
  - #text(fill: black, weight: "bold")[Accurate]
    - Often accuracy is traded off for remaining characteristics
    - E.g., accuracy vs interpretability, accuracy vs speed
  - #text(fill: black, weight: "bold")[Fast]
    - Reduce computational costs to train and test
    - E.g., real-time applications
  - #text(fill: black, weight: "bold")[Scalable]
    - Can handle large datasets efficiently (growing data and user
      bases)
    - E.g., in the Netflix prize, Netflix didn't end up implementing the
      best algorithm since it wasn't scalable enough

==== How Are Machine Learning Systems Organized?
<how-are-machine-learning-systems-organized>
- Machine learning systems organized in a #text(fill: black, weight: "bold")[pipeline]
  + #text(fill: black, weight: "bold")[Break down] problem into sub-problems
  + #text(fill: black, weight: "bold")[Solve] problems one at a time
  + #text(fill: black, weight: "bold")[Combine] solutions to solve initial problem
- Performance $p$ of a pipeline:
  $ p_(s y s t e m) = sum_i p_i dot.op alpha_i $ where:
  - $p_i$: Performance of each stage
  - $alpha_i$: Importance of each stage

==== Example of Photo OCR System
<example-of-photo-ocr-system>
- #text(fill: black, weight: "bold")[Goal];: build systems to read text in a picture
  - OCR = "Optical Character Recognition"
- #text(fill: black, weight: "bold")[Stages of ML pipeline for OCR:]
  - Text detection: find text areas in the picture
  - Character segmentation: split text into letter boxes
    - E.g., #text(fill: blue)[h e l l o]
  - Character classification: classify characters individually
  - Spelling correction: fix text errors using context
    - E.g., #text(fill: blue)[hell0] corrected to
      #text(fill: blue)[hello]
- #text(fill: black, weight: "bold")[Sliding window approach]
  - #text(fill: black, weight: "bold")[Problem];: Unknown text location and size
  - Text detection
    - Train classifier to recognize letters vs non-letters
    - Scan image in two directions with different sizes for text
    - Evaluate classifier cheaper than training
    - Create text likelihood map (e.g., heatmap) using classifier
      probabilities
    - Enclose text areas in boxes
    - Discard boxes not fitting aspect ratio (valid text width \>
      height)
  - Character segmentation
    - Use sliding window classifiers to find "breaks" between characters

==== Getting More Data
<getting-more-data>
- The ideal recipe for ML is: "low-bias algorithm + train on massive
  amount of data"

- Use learning curves to make sure we are taking advantage of more data

- The #text(fill: black, weight: "bold")[problem] is getting large amount of data

- Always ask yourself: #emph["how much work is to get 10x more data than
  we currently have?"]

- Often it is not that difficult:

  + Artificial data
    - E.g., synthesize or amplify data set
  + Collect and label by hand
    - E.g., crowd sourcing like Amazon Mechanical Turk

==== OCR Pipeline: Example of Artificial Data Synthesis
<ocr-pipeline-example-of-artificial-data-synthesis>
- How can we increase data set size?
  + Synthesize data set
    - Use font libraries to generate large training sets
    - Paste characters against random backgrounds
    - Apply scaling, distortion, adding noise, etc
  + Amplify a data set
    - Add examples by warping/distorting existing examples
- Transformations and noise should be specific to the application domain
  - E.g., Gaussian noise is not always appropriate

==== Ceiling Analysis for ML Pipeline
<ceiling-analysis-for-ml-pipeline>
- The most valuable resource is time

  - You work on optimization for months
  - Find out that the optimization doesn't make much difference

- #text(fill: black, weight: "bold")[Problem];: On which part of the pipeline should time/resource
  be spent?

- #text(fill: black, weight: "bold")[Solution];: Ceiling analysis to Analyze pipeline performance

  - Single number for system performance
    - E.g., accuracy for OCR
  - For each component:
    - Mock component with "oracle" (always give correct output)
    - Leave others untouched
    - Compute pipeline performance
  - Identify critical components by estimating performance improvement
    with 10% component improvement
  - Measure, don't guess!
