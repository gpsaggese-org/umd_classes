# Introduction and Motivation

* Machine Learning Explainability

- **Question**: _"A model predicts a patient has 92% chance of heart disease
  $\to$ should the doctor trust it?"_
  - Without explanation, even accurate models are unusable in high-stakes
    decisions

- **Problem**: ML models are increasingly used for decisions that affect
  people's lives
  - E.g., credit scoring, medical diagnosis, criminal sentencing, hiring
  - Stakeholders (e.g., doctors, judges, regulators) need to understand _why_ a
    prediction was made, not just _what_ it is

- **Definition**: _Explainability_ is the degree to which a human can understand
  the cause of a model's decision
  - Aka "Interpretable ML", "XAI" (Explainable Artificial Intelligence)

* Accuracy vs Interpretability

- **Key idea**: there is a fundamental tension between model _accuracy_ and
  _interpretability_

- **Example**:
  - Linear regression $\to$ interpretable but limited capacity
  - Deep neural networks $\to$ high capacity but opaque (_"black box"_)

- **Goal**: develop methods that
  - Explain black-box models _post-hoc_
  - Without sacrificing predictive performance

* Taxonomy of Explainability Methods

- Explainability methods can be classified along several axes

::: columns
:::: {.column width=55%}
- **By scope**
  - _Global_: explain the model's overall behavior
    - E.g., feature importance rankings, partial dependence plots
  - _Local_: explain a single prediction
    - E.g., _"why was this loan application rejected?"_

- **By model dependence**
  - _Model-specific_: exploit internal model structure
    - E.g., attention weights in transformers, decision paths in trees
  - _Model-agnostic_: treat the model as a black box
    - E.g., LIME, SHAP $\to$ work with any model

- **By output type**
  - Feature attributions (numeric importance scores)
  - Rules or decision sets
  - Example-based (prototypes, counterfactuals)

* Local vs. Global Explanations

- **Local Explanations**: Explain a single prediction for a specific input
    - E.g., _"This loan was rejected because income $<$ \$30k and
    debt-to-income ratio $>$ 0.6"_
  - _Methods_:
    - LIME, SHAP, Counterfactuals
  - _Pros_:
    - Actionable for the individual affected
    - Required by regulations (e.g., GDPR "right to explanation")

- **Global Explanations**: Explain the model's overall decision-making logic
    - E.g., _"Across all predictions, income and credit history are the two most
      important features"_
  - _Methods_: feature importance, partial dependence plots, global surrogates
  - _Pros_:
    - Help model developers debug and validate
    - Enable stakeholders to assess fairness across populations

- **Key idea**: local and global explanations are complementary
  - A complete picture requires both

* Model-Agnostic vs. Model-Specific Methods

- **Model-specific**:
  - Methods exploit the model's internal structure
    - Decision tree $\to$ follow the path from root to leaf
    - Linear model $\to$ read coefficients directly
    - Neural network $\to$ gradient-based saliency maps, attention weights
  - _Pros_: computationally efficient, structurally faithful
  - _Cons_: tied to one model class, not transferable

- **Model-agnostic**
  - Methods treat the model as a black box $f: X \to Y$
    - Only require input-output access $\to$ query $f(x)$ and observe predictions
  - E.g., LIME, SHAP, permutation importance, partial dependence
  - _Pros_: applicable to any model, comparable across models
  - _Cons_: can be computationally expensive, may not capture internal mechanisms

* Intrinsic Interpretability vs. Post-Hoc Explanation

- **Definition**: _intrinsically interpretable_ models are understandable by
  design, without any additional explanation method
  - The model _is_ the explanation
  - E.g., decision trees, linear models

- **Definition**: _post-hoc_ methods explain a model _after_ it has been trained
  - Applied to black-box models to extract understanding

- **Key idea**: the choice between intrinsic and post-hoc is a design decision

\begingroup \scriptsize
| **Aspect** | **Intrinsic** | **Post-Hoc** |
| --- | --- | --- |
| **When** | Built into model | Applied after training |
| **Examples** | Decision trees, linear models, GAMs | LIME, SHAP, saliency maps |
| **Faithfulness** | Perfect (model = explanation) | Approximate (explanation $\approx$ model) |
| **Flexibility** | Limited model complexity | Any model |
| **Risk** | May sacrifice accuracy | Explanation may not reflect true reasoning |
\endgroup

* Decision Trees and Rule-Based Models

- **Key idea**: decision trees are the canonical intrinsically interpretable
  model
  - Every prediction follows an explicit if-then path

::: columns
:::: {.column width=55%}
- **Algorithm**: classify by following a path from root to leaf
  1. At each node, evaluate a condition on a single feature
  2. Branch left or right based on the outcome
  3. Reach a leaf $\to$ output the prediction

- **Example**: _"Loan approved because income $> \$50$k AND debt ratio
  $< 0.4$"_

- **Limitations**:
  - Deep trees (hundreds of nodes) become hard to interpret
  - Unstable: small data changes can produce different trees
  - Limited expressiveness for complex decision boundaries

- **Remark**: rule-based models (e.g., decision lists, rule sets) offer similar
  interpretability by expressing predictions as a collection of if-then rules

* Linear and Generalized Additive Models (GAMs)

- **Key idea**: linear models explain predictions through _additive feature
  contributions_
  - Each feature $x_j$ contributes $\beta_j x_j$ to the prediction
  - Coefficient $\beta_j$ quantifies feature $j$'s effect

- **Definition**: a _linear model_ predicts:
  $$
  \hat{y} = \beta_0 + \beta_1 x_1 + \beta_2 x_2 + \cdots + \beta_p x_p
  $$
  - **Interpretation**: increasing $x_j$ by one unit changes $\hat{y}$ by
    $\beta_j$, holding all else equal

- **Definition**: a _Generalized Additive Model_ (GAM) extends to nonlinear
  features:
  $$
  \hat{y} = \beta_0 + f_1(x_1) + f_2(x_2) + \cdots + f_p(x_p)
  $$
  - Each $f_j$ is a smooth, potentially nonlinear function (e.g., spline)
  - _Pros_: captures nonlinear patterns while remaining additive; each feature's
    effect can be plotted independently
  - _Cons_: cannot capture feature interactions unless explicitly added as
    $f_{jk}(x_j, x_k)$ terms

* Feature Attribution Methods: Overview

- **Definition**: _feature attribution_ assigns a numeric importance score
  $\phi_j$ to each input feature $x_j$ for a given prediction

- **Goal**: answer _"how much did each feature contribute to this prediction?"_

- **Key idea**: different methods define _"contribution"_ differently

* SHAP: Shapley Values Foundation

- **Key idea**: SHAP (Lundberg and Lee, 2017) uses _Shapley values_ from
  cooperative game theory to fairly distribute the prediction among features

- **Definition**: the Shapley value $\phi_j$ for feature $j$ is:
  ```{=typst}
  $ phi_j = sum_(S subset.eq N without {j}) ((|S|)! (|N| - |S| - 1)!) / (|N|)! (f(S union {j}) - f(S)) $
  ```
  where:
  - $N$ = set of all features
  - $S$ = a subset excluding feature $j$
  - $f(S)$ = model prediction using only features in $S$

- The sum averages the _marginal contribution_ of $j$ over all possible orderings

* SHAP: Intuition and Example
- **Setup**
  - 3 friends `A` (Alice), `B` (Bob), `C` (Carol) work together
  - They earn \$100k on a project
  - How do you split it fairly if each contributes differently?

- **Problem**: contributions are "contextual", i.e., depend on order and who
  participates
  - `A` alone earns $40k
  - `A` + `B` together earn \$90k, `B` adds \$50k when `A` is there
  - `A` + `B` + `C` earn \$100k, `C` adds \$10k when both are there
  - But if `C` came first, she might have contributed $60k

- **Idea**
  - Try every possible order they could have joined
  - Compute each person's marginal contribution in that order
  - Average to compute the Shapley value of each person

- **Setup**: predicting house price with three features
  - Baseline (no features): \$200k
  - Predicted price: \$300k
  - Three features: Bedrooms ($B$), Location ($L$), Square footage ($S$)

- There are $3! = 6$ possible orderings; for each, compute marginal contribution:

  1. Order $B \to L \to S$: $B$ adds \$30k, $L$ adds \$50k, $S$ adds \$20k
  2. Order $L \to B \to S$: $L$ adds \$40k, $B$ adds \$35k, $S$ adds \$25k
  3. Order $B \to S \to L$: $B$ adds \$25k, $S$ adds \$40k, $L$ adds \$35k
  4. ... (three more orderings)

- Shapley value for $B$ = average of $B$'s contribution across all 6 orderings
  $\approx$ \$30k
  - Similarly for $L$ and $S$
- Total: \$30k + \$50k + \$20k = \$100k gain from baseline

- **Remark**: the formula sums over all $2^p$ coalitions, not just orderings, but
  the intuition is identical

* SHAP: Properties and Computation

- **Properties**:
  - SHAP satisfies desirable properties
  - _Efficiency_: values sum to the prediction difference from baseline
  - _Symmetry_: features with identical contributions get equal attribution
  - _Dummy_: features that never change the prediction get $\phi_j = 0$
  - _Additivity_: for ensemble models, SHAP values of the ensemble equal the
    average of individual SHAP values

- **Problem**: exact computation requires $2^p$ model evaluations (exponential in
  the number of features)

- **Solution**: efficient approximations exist
  - `KernelSHAP`: weighted regression approximation (model-agnostic)
  - `TreeSHAP`: for tree-based models
  - `DeepSHAP`: backpropagation-based for neural networks

* SHAP: Visualization and Interpretation

- **Key idea**: SHAP allows visualization for both local and global explanations

- **Local explanation** (single prediction):
  - _Force plot_: shows how each feature pushes the prediction from the baseline
    $\mathbb{E}[f(x)]$ toward the final output $f(x)$
  - E.g., _"This house is priced \$50k above average because it has 4
    bedrooms (+\$30k) and is near a school (+\$20k)"_

- **Global explanation** (entire dataset):
  - E.g., _"Square footage and location are the two most important features
    across all predictions"_
  - _Summary plot_: shows the distribution of SHAP values for each feature
    across all data points
  - _Dependence plot_: shows how one feature's SHAP value varies with its
    actual value, revealing nonlinear effects

* LIME: Local Interpretable Model-agnostic Explanations

- **Key idea**: approximate a complex model _locally_ with a simple,
  interpretable model (Ribeiro et al., 2016)

::: columns
:::: {.column width=55%}
- **Algorithm**:
  1. Pick an instance $x$ to explain
  2. Generate perturbed samples $\{z_1, ..., z_N\}$ around $x$
  3. Weight each $z_i$ by proximity to $x$ using a kernel $\pi_x(z_i)$
  4. Query the black-box model $f()$ on all $z_i$ to get predictions $f(z_i)$
  5. Fit a simple model $g$ (e.g., linear) on $\{(z_i, f(z_i))\}$ weighted by
     $\pi_x$

- **Example**: a spam classifier flags an email
  - LIME reveals the words `"free"`, `"winner"`, and `"click here"` drove the
    prediction
  - The linear explanation assigns a positive coefficient to each of these tokens

* LIME: Formal Objective

- **Definition**: LIME finds the best local explanation by solving:

  ```{=typst}
  $ g^* = op("arg min")_(g in G) sum_(i=1)^N pi_x(z_i) (f(z_i) - g(z_i))^2 + Omega(g) $
  ```
  where:
  - $f()$ is the function to explain
  - $G$ is restricted to a class of inherently interpretable models $g()$
  - $z_i$ are perturbed samples around the point to interpret $x$
  - $\pi_x(z_i)$ is the locality kernel
    $\exp(-\frac{D(x, z_i)^2}{\sigma^2})$
  - $\Omega(g)$ penalizes complexity of the explanation (e.g., number of non-zero
    coefficients)

- **Interpretation**: LIME minimizes weighted reconstruction error between the
  black-box $f$ and the simple surrogate $g$, with more weight on samples close
  to $x$

- **Intuition**: The locality kernel

* LIME: Limitations
- LIME solves
  ```{=typst}
  $ g^* = op("arg min")_(g in G) sum_(i=1)^N pi_x(z_i) (f(z_i) - g(z_i))^2 + Omega(g) $
  ```

- Explanations depend on the perturbation strategy
  - Different perturbations can yield different explanations
    $\exp(-\frac{D(x, z_i)^2}{\sigma^2})$

- The kernel width is a hyperparameter that affects locality
  - No theoretical guarantees on faithfulness to the original model

* Permutation Feature Importance

- **Key idea**: measure how much the model's performance _degrades_ when a
  feature's values are randomly shuffled (Breiman, 2001)

- **Algorithm**:
  1. Compute baseline performance $P_0$ on the validation set
  2. For each feature $j$:
     - Randomly permute the values of $x_j$ across all samples
     - Compute the new performance $P_j$
     - Importance of feature $j$:

       ```{=typst}
       $ phi_j = P_0 - P_j $
       ```

  3. Repeat and average over multiple permutations for stability

- **Interpretation**: a large drop $\phi_j$ means the model relies heavily
  on feature $j$

- **Pros**:
  - Model-agnostic, global, easy to implement
  - Directly tied to predictive performance

- **Cons**:
  - Breaks feature correlations $\to$ can produce unrealistic data points
  - Correlated features split importance (e.g., height and weight)
  - Only measures _predictive_ importance, not _causal_ importance

* Comparing Feature Attribution Methods

- **Key idea**: SHAP, LIME, and permutation importance each have distinct
  strengths $\to$ choice depends on the use case

\begingroup \scriptsize
| **Property** | **SHAP** | **LIME** | **Permutation Importance** |
| --- | --- | --- | --- |
| **Scope** | Local (aggregable to global) | Local | Global |
| **Theory** | Shapley axioms | Local fidelity | Performance degradation |
| **Consistency** | Guaranteed | Depends on perturbations | Stable with enough repeats |
| **Speed** | Slow (exact), fast (TreeSHAP) | Moderate | Fast |
| **Interactions** | Captures via coalition structure | Ignores (linear surrogate) | Ignores |
| **Correlation handling** | Conditional vs marginal variants | Perturbs independently | Breaks correlations |
\endgroup

- **Remark**: in practice, using multiple methods and checking agreement
  increases confidence in the explanation

# Counterfactual Explanations

* Counterfactual Explanations

- **Definition**: a _counterfactual explanation_ identifies the smallest change
  to the input that would _flip_ the model's decision (Wachter et al., 2017)
  - _"What would need to change for the outcome to be different?"_

- **Example**: a loan application is denied
  - Counterfactual: _"If your income were \$5k higher and you had no
    outstanding defaults, the loan would be approved"_
  - This tells the applicant _what to change_, not just _why it was rejected_

::: columns
:::: {.column width=55%}
- **Key idea**: counterfactuals are _actionable_ $\to$ they suggest a path
  from the current outcome to the desired one

- **Properties of good counterfactuals**:
  - _Proximity_: as close as possible to the original input
  - _Sparsity_: change as few features as possible
  - _Plausibility_: the counterfactual should be realistic
  - _Actionability_: only change features the user can control
    - E.g., age and race are immutable
::::
:::: {.column width=45%}

* Counterfactual Explanations: Formal Framework

- **Definition**: find a counterfactual $x'$ by solving:

  ```{=typst}
  $ x' = op("arg min")_(x') d(x, x') quad "subject to" quad f(x') = y' $
  ```

  - $x$ = original input, $y'$ = desired outcome
  - $d(dot, dot)$ = distance function measuring how much the input changes

- **Remark**: in practice, a soft constraint formulation is used:

  ```{=typst}
  $ x' = op("arg min")_(x') lambda dot.op ell(f(x'), y') + d(x, x') $
  ```

  - $ell$ is a loss penalizing predictions far from $y'$
  - $lambda$ controls the tradeoff between achieving $y'$ and staying close to $x$

- **Limitations**:
  - Multiple valid counterfactuals may exist $\to$ which one to present?
  - Counterfactuals may lie outside the data manifold (unrealistic)
  - Sensitive to the choice of distance metric $d$

# Explainability in Bayesian Models

* Explainability in Bayesian Models

- **Key idea**: Bayesian models provide a natural form of explainability through
  _uncertainty quantification_
  - Instead of a single point prediction, they output a full posterior
    distribution over outcomes

- **Intuition**: a model that says _"I predict 80% chance of disease, but I'm
  very uncertain"_ is more informative than one that just says _"disease"_

- **Definition**: in Bayesian inference, we update our belief about parameters $\theta$ given data $cal(D)$:

  ```{=typst}
  $ Pr(theta | cal(D)) = frac(Pr(cal(D) | theta) dot.op Pr(theta), Pr(cal(D))) $
  ```

  where the numerator is (likelihood) × (prior) and denominator is (evidence)

- **Remark**: the posterior is inherently interpretable $\to$ it tells us which
  parameter values are plausible and how confident we should be

* Interpreting Posterior Distributions and Credible Intervals

- **Key idea**: the shape of the posterior distribution directly communicates
  model uncertainty about each parameter

- **Definition**: a _credible interval_ [$\theta_L$, $\theta_U$] contains the true parameter with probability $1 - \alpha$:

  ```{=typst}
  $ Pr(theta_L lt.eq theta lt.eq theta_U | cal(D)) = 1 - alpha $
  ```

- **Interpretation**:
  - _Narrow_ posterior $\to$ model is confident about θ
  - _Wide_ posterior $\to$ high uncertainty, need more data
  - _Multimodal_ posterior $\to$ multiple plausible explanations exist

- **Example**: predicting treatment effect
  - Posterior mean = 5.2 units, 95% credible interval = [1.1, 9.3]
  - _"The treatment likely has a positive effect, but we're uncertain about its magnitude"_

- **Remark**: credible intervals have a direct probability interpretation, unlike frequentist confidence intervals

* Bayesian Networks and Probabilistic Graphical Models

- **Key idea**: Bayesian Networks (BNs) encode _conditional independence_
  relationships as a directed acyclic graph (DAG) $\to$ the structure itself
  is an explanation

::: columns
:::: {.column width=55%}
- **Definition**: a Bayesian Network is a pair ($cal(G)$, $Pr$) where:
  - $cal(G)$ = DAG whose nodes represent random variables
  - $Pr$ = joint distribution factored according to $cal(G)$:

    ```{=typst}
    $ Pr(X_1 , ... , X_n) = product_(i = 1)^n Pr(X_i | "Parents"(X_i)) $
    ```

- **Interpretation**:
  - Edges encode direct dependencies
  - Missing edges encode conditional independencies
  - The graph answers _"what influences what?"_

- **Example**: _"The model predicts high risk because Smoking $\to$ Cancer
  $\to$ Mortality"_ $\to$ the causal pathway is visible in the graph

* Uncertainty Quantification as a Form of Explanation

- **Key idea**: knowing _what the model doesn't know_ is itself an explanation
  $\to$ uncertainty quantification (UQ) distinguishes confident from unreliable
  predictions

- **Definition**: two types of uncertainty
  - _Aleatoric_ (data uncertainty): irreducible noise in the data
    - E.g., inherent randomness in patient outcomes
  - _Epistemic_ (model uncertainty): reducible with more data
    - E.g., model hasn't seen enough examples of a rare condition

- **Interpretation**: a Bayesian model decomposes total predictive uncertainty:

  ```{=typst}
  $ "Var"[Y | x, cal(D)] = "E"["Var"[Y | x, theta]] + "Var"["E"[Y | x, theta]] $
  ```

  where the first term is aleatoric (data) uncertainty and the second is epistemic (model) uncertainty

- **Example**: a medical diagnosis model
  - High aleatoric uncertainty $\to$ _"This case is inherently ambiguous"_
  - High epistemic uncertainty $\to$ _"We haven't seen enough cases like this,
    collect more data"_

- **Remark**: models that flag high epistemic uncertainty enable _safe
  deployment_ $\to$ defer to human experts when the model is unsure

# Causal AI and Explainability

* Causal AI and Explainability

- **Problem**: most ML explanations are _correlational_ $\to$ _"feature $X$ is
  associated with outcome $Y$"_ does not mean _"$X$ causes $Y$"_

- **Question**: _"Does the model's explanation reflect a true causal mechanism,
  or just a spurious correlation in the training data?"_

- **Key idea**: causal AI provides tools to distinguish _why_ something happens
  from _what_ co-occurs
  - Pearl's _Ladder of Causation_ (2018):
    1. _Association_ (seeing): $Pr(Y | X)$ $\to$ observational
    2. _Intervention_ (doing): $Pr(Y | do(X))$ $\to$ experimental
    3. _Counterfactual_ (imagining): $Pr(Y_x | X = x', Y = y')$ $\to$
    retrospective

- **Remark**:
  - Standard ML operates at level 1 (association)
  - Causal explanations require level 2 or 3

* Counterfactual Reasoning in Causal Frameworks

- **Key idea**: causal counterfactuals differ from predictive counterfactuals
  - Predictive counterfactuals: _"Given observations, what's the best guess
    about an outcome under different conditions?"_
  - Causal counterfactuals: _"What would have happened to this individual if I
    had intervened and changed one thing?"_

- **Definition**: causal counterfactual _"$Y$ had $X$ been $x$"_ for an
  individual with observed $(X = x', Y = y')$ is computed in three steps:
  1. _Abduction_infer exogenous variables $U$ from observations
     {=typst} 
     $ Pr(U | X = x' , Y = y') $
  2. _Action_: modify structural equation for $X$ to $do(X = x)$
  3. _Prediction_: compute counterfactual outcome $Y_x$ under modified model
     with inferred $U$

- **Example**: a patient received treatment A and recovered
  - Counterfactual: _"Would the patient have recovered with treatment B?"_
  - Requires full SCM, not just observational data

- **Remark**: causal counterfactuals are more demanding than interventional
  queries since require individual-level reasoning

* Distinguishing Causal Explanations from Feature Attribution

- **Problem**: feature attribution methods (SHAP, LIME) answer _"what features
  are important for the model's prediction?"_ but not _"what features actually
  cause the outcome?"_

::: columns
:::: {.column width=55%}
- **Key idea**: there is a crucial difference between:
  - _Model explanation_: why did the model predict $\hat{y}$?
  - _Causal explanation_: what actually caused outcome $y$?

- **Example**: predicting hospital readmission
  - SHAP says _"number of prior visits"_ is the top feature
  - But prior visits don't _cause_ readmission, they are a proxy for underlying
    disease severity
    - E.g., _"reduce the number of prior visits"_ doesn't help
  - Leads to misguided interventions
  - A causal analysis would identify the actual mechanism

- **Remark**: conflating model explanations with causal explanations is
  a common and dangerous mistake

# Quality of Explanations

* Quality of Explanations

- Evaluating explanation quality requires checking:
  1. _Faithfulness_: does it reflect the model?
  2. _Stability_: is it consistent across similar inputs?
  3. _Robustness_: can it be gamed or manipulated?

* Faithfulness of Explanations

- **Definition**: an explanation is _faithful_ if it accurately reflects the
  model's actual reasoning process
  - A faithful explanation describes _how the model truly works_, not just a
    plausible story

- **Problem**: post-hoc explanations are approximations and may not accurately
  represent the model's internal logic
  - LIME's linear surrogate may miss nonlinear interactions
  - SHAP with marginal expectations may attribute importance to features the
    model never uses conditionally

- **Example**: testing faithfulness
  - Remove the top-$k$ features according to the explanation
  - If the prediction doesn't change $\to$ the explanation is unfaithful
  - If it changes dramatically $\to$ the explanation is likely faithful

* Stability and Robustness of Explanations

- **Definition**: an explanation is _stable_ if small changes to the input
  produce small changes in the explanation
  - Aka _"continuity"_ or _"smoothness"_

- **Problem**: many explanation methods are _unstable_
  - LIME: different random perturbations yield different explanations for the
    same input
  - Gradient-based methods: explanations can be noisy and visually
    incoherent

- **Definition**: an explanation is _robust_ if it cannot be manipulated by
  adversarial perturbations
  - Slack et al. (2020): showed that biased models can be made to produce
    _fair-looking_ LIME/SHAP explanations via adversarial scaffolding

- **Key idea**: unreliable explanations are worse than no explanations
  - They create false confidence in flawed models
  - Stakeholders make decisions based on explanations they trust

* The Accuracy-Interpretability Tradeoff

- **Key idea**: the _accuracy-interpretability tradeoff_ is the central tension
  in explainable ML

::: columns
:::: {.column width=55%}
- **Intuition**: as models grow more complex, they capture more patterns in the
  data (higher accuracy) but become harder to understand

// TODO(ai_gp): Convert it into a table
- **Spectrum**:
  - Linear regression $\to$ fully interpretable, limited capacity
  - Decision trees $\to$ interpretable if shallow, brittle
  - GAMs $\to$ nonlinear but additive, moderate interpretability
  - Random forests / gradient boosting $\to$ high accuracy, low
    interpretability
  - Deep neural networks $\to$ highest capacity, opaque

- **Question**: _"Is this tradeoff fundamental, or can we have both?"_
  - Recent work (Rudin, 2019) suggests _some_ domains allow high accuracy with
    interpretable models 
  - But for many tasks, the gap remains significant

- **Remark**: Rudin (2019) argues we should prefer inherently interpretable
  models in high-stakes settings rather than explaining black boxes post-hoc
