# Effect heterogeneity

* From ATE to CATE
- @Comparison@
  - **Average Treatment Effect (ATE)** 
    - Answers _"Should we roll out a treatment to entire population?"_
    - Computes $\EE[Y_1 - Y_0]$ 

  - **Conditional Average Treatment Effect (CATE)**
    - Answers
      - _"Which units should we treat?"_
      - _"What's the optimal treatment for each unit?"_
    - Enables personalization, since each unit is different in terms of its
      covariate $X$
    - Computes $\EE[Y_1 - Y_0 | X]$ 

* Conditional Average Treatment Effect
- @Example@: you have customers and a treatment effect $T \to Y$
  - $T$ = treatment (discount, advertisement exposure, recommendation, pricing
    change, etc.)
  - $Y$ = outcome (purchase amount, satisfaction, churn probability, etc.)
  - You want to personalize the treatment
    - E.g., different discounts to different customers

- @Definition@: **unit response to a treatment** measures how the outcome $Y$
  changes when the treatment $T$ changes slightly, holding all the other factors
  fixed
  $$\frac{\Delta Y}{\Delta T}\Big|_{X=x}$$
- Aka "treatment effect", "marginal effect", "treatment sensitivity"

- @Key insight@: It's like customer segmentation
  - Create groups of customers based on how they respond to your treatment
  - E.g., some customers reacts well to discounts, others poorly
  - E.g., high / medium / low treatment effect

* Why Prediction Is Not the Answer
- @Fact@: Predictive models estimate
  - Outcome $Y = f(X, T)$
    - E.g., low vs high sales
  - Not treatment sensitivity $\frac{\Delta Y}{\Delta T}\Big|_{X=x}$
    - E.g., high discount sensitivity

- @Problem@: treatment slopes are non-observable at unit level
  - Fundamental problem of causal inference: you cannot observe same unit under
    multiple treatment conditions
  - Therefore cannot directly compute treatment sensitivity and ML can't predict
    it

* Restaurant Discount: Example
- @Problem@
  - A chain of restaurants operate across the country and needs to understanding
    when it should give discounts to its customers
  - Run a nationwide experiment, where it randomized discounts in different
    restaurants in the chain
  - The unit of treatment is $(day, restaurant)$

- @Solution@
- Linear regression with treatment-covariate interactions estimates CATE
  - Model:
    $y_i = \beta_0 + \beta_1 t_i + \beta_2 X_i + \beta_3 t_i X_i + e_i$
  - The interaction term $t_i \cdot X_i$ (treatment $\cdot$ covariate) is the
    simplest way to make the slope depend on the covariate
  - Each unit with different $X_i$ gets a different slope prediction despite
    unobservable slopes

- You can estimate the model and then use the coefficients to compute the CATE
  - Slope is $\frac{\partial y_i}{\partial t_i} = \beta_1 + \beta_3 X_i$

  - @Shortcut@: predict the outcome at $t+1$ and at $t$, then subtract
    $$CATE_i = \hat{y}_i(t+1) - \hat{y}_i(t)$$
    - For this linear model, the difference equals the same slope
      $\beta_1 + \beta_3 X_i$, since the effect doesn't depend on $t$

- If the treatment was not randomized, then we will need to do identification
  removing confounding

* Evaluating CATE Predictions
- @Problem@: CATE looks like a standard ML prediction problem, but the target
  is never observable
  - _"$Y_{1i}$ and $Y_{0i}$ are never observed for the same unit"_
    (fundamental problem of causal inference)
  - Cannot compute standard ML metrics (e.g., MSE) on
    $$
    \tau(x) \defeq \EE[Y_1 - Y_0 | X = x]
    $$

- @Solution@: replace unit-level ground truth with group-level evaluation
  1. Partition data by model predictions, and estimate the effect within each
     partition instead of per unit
  2. Use a train/test split, so the CATE model is evaluated on held-out data it
     wasn't fit on

* CATE Algorithm
1. Fit the CATE model on training data

   ::: small-code
   ```python
   regr_model = smf.ols("sales ~ discounts*(month + weekday + ...)",
                        data=train).fit()
   ```
   :::

2. Predict CATE values on test data

   ::: small-code
   ```python
   test_pred = (regr_model.predict(
                  test.assign(discounts=test["discounts"]+1))
              - regr_model.predict(test))
   ```
   :::

3. Partition test data (by quantiles of those predictions)
   
   ::: small-code
   ```python
   # Divide test data into 10 groups based on predicted CATE values
   quantiles = pd.qcut(test_pred, q=10)
   # Low quantile: days with low predicted CATE
   # High quantile: days with high predicted CATE
   ```
   :::

4. Estimate group effects (regression within each group)

   ::: small-code
   ```python
   effect = regress(sales ~ discounts)
   ```
   :::

5. Evaluate
   - Do the effects match the predictions?
   - If your CATE predictions are good:
     - Quantile 1 (low prediction) $\to$ low actual effect
     - Quantile 10 (high prediction) $\to$ high actual effect
   - Monotonic staircase pattern $\implies$ good model
   - Random model produces flat curve (same effect in all quantiles = ATE)

* Cumulative Effect
- @Definition@: **Cumulative effect curve** shows the effect by cumulative sample
  percentage

- @Algorithm@:
  - Sort data by CATE score
  - Accumulate groups sequentially
  - Estimate effect on top 1%, then top 2%, then top 3%, etc

- @Fact@: the curve shape identifies a good vs bad model
  - Well-ordered model: starts high, gradually converges to ATE
  - Bad model: quickly converges to ATE or fluctuates around it

* Cumulative Gain
- @Definition@: **Cumulative gain** measures how much value a CATE model captures
  by sequentially treating units with highest predicted effects

- Multiply cumulative effect by cumulative sample proportion:
  $$
  \text{Gain} = \frac{N_{\text{cumulative}}}{N_{\text{total}}} \times (\text{effect} - ATE)
  $$
  - Downscales early portion where sample size (and confidence) is small
  - Centers around zero, with gains relative to population average effect

- @Interpretation@
  - Well-ordered model: steep initial climb, then plateaus near ATE
  - Random model: flat line (no gain above ATE anywhere)
  - Enables visual model comparison on a single plot

* Area Under Curve (AUC)

- @Definition@: area under the cumulative gain curve aggregates CATE model quality
  into a single summary metric

- @Intuition@
  - Larger AUC = better CATE ordering
  - AUC = 0 if model predicts constant effect (equivalent to random assignment)
  - AUC > 0 indicates true heterogeneity in treatment response

- @Application@
  - Automates model selection among competing CATE approaches
  - Enables hyperparameter tuning via grid search or Bayesian optimization

# Metalearners

* Metalearners
- **Goal**: Estimate conditional average treatment effect (CATE) to identify how
  unit $i$ responds differently to treatment
  $$\tau_i(x) \triangleq \EE[Y_i(1) - Y_i(0) | X]$$

- **Definition**: metalearners leverage / recycle off-the-shelf machine learning
  algorithms for treatment effect estimation
  - Can estimate ATE but mainly used for CATE estimation
  - Work well with high-dimensional data

- Often this is a _ranking problem_: correctly order units by treatment
  sensitivity
  - Discrete treatments: binary or categorical
  - Continuous treatments: dose, price, discount level

* Marketing Email: Example
- Marketing team at an online retailer

- **Goal**: Determine which customers are receptive to a marketing email
  - The email has potential to increase customer spending

- **Problem**:
  - Your budget of discount is limited 
  - Some customers don't like receiving marketing emails
    - Avoid sending email to unreceptive customers to maintain relationship
      quality

- **Solution**: 
- Estimate CATE of email on customers' future purchase volume

- Data
  - Historical data about sending emails to fit CATE model
  - Data from experiments where emails were randomized (use for evaluation)

- The treatment variable is `mkt_email`
- The outcome variable is `next_mnth_pv` (purchase volume one month after sending
  the email)
- Covariates (e.g., age, time since first purchase, how much bought on each
  category)

* T-Learner
- **Approach**: Fit separate outcome models for each treatment level
  - For binary treatment: estimate
    $\mu_0(x) = \EE[Y | T=0, X]$ and 
    $\mu_1(x) = \EE[Y | T=1, X]$
  - Predict both potential outcomes for each unit and then estimate CATE as:
    $$\hat{\tau}(x)_i = \hat{\mu}_1(X_i) - \hat{\mu}_0(X_i)$$

- **Advantages**: Simple and straightforward implementation

- **Disadvantage**: Prone to regularization bias

* Regularization Bias
- **Problem**: In T-learner you need to fit two models at the same time
  - If treated data is sparse, $mu_1$ becomes overly regularized and simple
    (e.g., a constant)
  - If untreated data is abundant, $mu_0$ can fit a non-linearity

- **Result**:
  - Bias in CATE estimation (nonlinear difference minus linear difference)
  - E.g., model with nonlinear outcome but constant treatment effect produces
    wrong nonlinear CATE
  - In imbalanced data, regularization creates artificial heterogeneity

* X-Learner
- **Approach**
  - Address regularization bias of T-learner
  - Two-stage approach with propensity score weighting
  - Performs better when one treatment group is much larger than the other

- **Stage 1**: Fit initial outcome models (same as T-learner)
  - $\mu_0(X)$ and $\mu_1(X)$ for control and treated groups

- **Stage 2**: Estimate imputed treatment effects
  - For control units: estimate missing treatment outcome:
    $$\hat{\tau}(X, T=0) = \hat{\mu}_1(X, T=0) - Y_{T=0}$$
  - For treated units: estimate missing control outcome:
    $$\hat{\tau}(X, T=1) = Y_{T=1} - \hat{\mu}_0(X, T=1)$$

- **Stage 3**: Fit effect models
  - Fit $\hat{\mu}_{\tau 0}(x)$ to predict $\hat{\tau}(X, T=0)$
  - Fit $\hat{\mu}_{\tau 1}(x)$ to predict $\hat{\tau}(X, T=1)$

- **Pros**
  - X-learner shines when large imbalance between treatment and control groups

* X-Learner With Weighting Scheme
- Combine second-stage models using propensity score $\hat{e}(x) = \Pr(T=1|X)$
  $$\hat{\tau}(x) 
  = \hat{\mu}_{\tau 0}(x) \cdot \hat{e}(x) + 
    \hat{\mu}_{\tau 1}(x) \cdot (1 - \hat{e}(x))$$

- **Intuition**
  - When treatment is rare: $\hat{e}(x)$ is small, down-weights flawed
    $\hat{\mu}_{\tau 0}$
  - When treatment is common: $1 - \hat{e}(x)$ is large, up-weights correct
    $\hat{\mu}_{\tau 1}$
  - Automatically emphasizes the model trained on larger sub-sample

* Metalearners for Continuous Treatments
- **Problem**: Randomized discount experiment at restaurant chain
  - Goal: which days should discounts be highest?
  - Treatment: discount amount (continuous, 0-40%)
  - Outcome: sales volume one day later

- **Insight**
  - Customers more sensitive to prices on some days (e.g., holidays)
  - CATE tells us how much demand increases per unit discount
  - High CATE days $\Rightarrow$ use more discounts
  - Low CATE days $\Rightarrow$ use fewer

- **Problem**
- Discrete approaches fail because they
  - Can't fit separate models for each discount level (infinite treatments)
  - Need methods that handle continuous treatment as a feature or component

- **Solution**: S-learner and Double-ML

* S-Learner
- **Approach**: Single machine learning model that includes treatment $T$ and
  covariates $X$ to predict outcome $Y$
  - Goal is to estimate $\mu_s(x, t) = E[Y | T, X]$
  - "S-Learner" since it's "single"
  - This model doesn't output treatment effect, rather it outputs counterfactual
    predictions (i.e., predictions under different treatment regimes)

- **For binary treatment**: CATE = $\mu_s(X_i, T=1) - \mu_s(X_i, T=0)$

- **For continuous treatment**: Extended procedure needed
  - Create grid of treatment values (e.g., [0, 10, 20, 30, 40] for discounts)
  - Compute predictions for all treatment level
  - Summarize as slope via simple linear regression to extract CATE
  - Formula: $\beta = \text{Cov}(t, y) / \text{Var}(t)$

- **Pros**:
  - Simple
  - Supports both binary and continuous treatments
  - Performs reasonably well

- **Cons**:
  - Biases treatment effect toward zero
  - Treatment variable can be completely discarded if weak relative to other
    covariates

- **Solution**:
  - Use Double/Debiased Machine Learning (R-learner) to address bias

* S-Learner: Implementation Steps

- **Step 1**: Train single model on all data
  - `s_learner.fit(X + [T], y)` where T is treatment feature

- **Step 2**: Create counterfactual grid
  - Define treatment grid: e.g., $[0, 10, 20, 30, 40]$
  - Cross-join with test set: each test unit at each treatment level
  - Makes predictions on expanded grid

- **Step 3**: Extract slopes
  - Group by unit, apply linear regression
  - Extract slope coefficient as unit-level CATE
  - Can also use slope formula directly:
    $\hat{\beta} = \text{Cov}(t,y) / \text{Var}(t)$

- **Result**: CATE prediction for each unit

* S-Learner: The Bias Problem

- **Problem**
  - ML models are regularized by default
  - Regularization can suppress treatment effect unless treatment signal is very
    strong
  - ML model may discard treatment feature entirely
  - Distribution of estimated ATE is shifted toward zero compared to true effect

- **Solution**
  - Use orthogonalization techniques

* R-learner (Double/Debiased Machine Learning)

- **The principle**:
  - Use ML to model confounding relationships
  - Orthogonalize treatment and outcome from confounders
  - Extract treatment effect from residuals

- **The equation**
  - $\widetilde{Y}_i = Y_i - \hat{\mu}_y(X_i)$ (outcome residual)
  - $\widetilde{T}_i = T_i - \hat{\mu}_t(X_i)$ (treatment residual)
  - Regress residuals: $\widetilde{Y}_i = \tau \widetilde{T}_i + \varepsilon_i$

- **Why it works**
  - $\hat{\mu}_y$ captures confounding effects on outcome
  - $\hat{\mu}_t$ captures confounding effects on treatment
  - Residuals are "as if" treatment was randomized

- **Key requirement**: no unobserved confounders

* Double-ML: the Overfitting Problem

- **Stage 1**: Estimate nuisance parameters
  - Focus on treatment effect $\tau$ (or CATE $\tau(X)$)
  - Estimate nuisance parameters (what we are not interested in) to obtain
    parameter of interest
  - _Step 1_: Estimate outcome model $\hat{\mu}_y(X)$
    - Fit ML regression model to predict outcome $Y$ from features $X$
    - E.g., capture nonlinear confounding relationships between $X$ and $Y$
    - Use cross-validation predictions to prevent overfitting
  - _Step 2_: Estimate treatment model $\hat{\mu}_t(X)$
    - Fit ML regression model to predict treatment $T$ from features $X$

- **Stage 2**: Compute residuals
  - _Step 3_: Residualize outcome $\widetilde{Y} = Y - \hat{\mu}_y(X)$
  - _Step 4_: Residualize treatment $\widetilde{T} = T - \hat{\mu}_t(X)$
    - Residuals represent part of $Y$ and $T$ independent of $X$
    - Confounding is removed and can estimate treatment effect without bias

- **Stage 3**: Construct the causal target
  - _Step 5_: Create transformed outcome
    $Y^* = \frac{\widetilde{Y}}{\widetilde{T}}$
    - Dividing gives "slope" of relationship between treatment and outcome
      residuals, i.e., estimate of $\tau(X_i)$
  - _Step 6_: Create weights $w_i = \widetilde{T}_i^2$
  - Dividing by $\widetilde{T}$ introduces noise
  - Squared weights down-weight noisy estimates, up-weight stable estimates

- **Stage 4**: Estimate the CATE Model
  - _Step 7_: Fit final ML model to predict $Y^*$ from $X$, using weights $w_i$
    - Train ML regression model on $(Y^*, X)$
    - Use weights $w_i$ for stable, low-noise predictions
    - Learn how treatment effect varies with features $X$
    - Model predictions give heterogeneous treatment effects

* Double-ML for CATE Estimation

- Allow causal parameter to vary with covariates $\tau(X_i)$
  - Outcome model:
    $$Y_i = \hat{\mu}_y(X_i) + \tau(X_i) \cdot \widetilde{T}_i + \varepsilon_i$$

- You can isolate the error, which is called "R-loss" and can be used as a causal
  objective function
  $$\hat{L}_n(\tau(x)) = \frac{1}{n} \sum_{i=1}^{n} (\widetilde{Y}_i - \tau(X_i)
  \widetilde{T}_i)^2$$
  - Minimizing this loss directly estimates CATE

# Difference-in-differences

## Canonical Difference-in-Differences

* Data Structures: Definition

- Data can have different temporal and cross-sectional patterns
  - Causal relationships can be estimated depending on the data structure

- **Definition**:
  - _Cross-sectional data_: multiple units observed at a single point in time
    - E.g., snapshot of sales across restaurants with/without discounts
    - E.g., student test scores across schools in a single academic year
  - _Panel data_ (aka _longitudinal data_): same units observed repeatedly over
    time
    - E.g., same restaurants before/after discount implementation
    - E.g., same students' test scores tracked across multiple year
  - _Repeated cross-sectional data_: different units observed at multiple time
    points
    - E.g., different restaurant samples in year 1 and year 2
    - E.g., different student samples from schools surveyed in 2020 and 2025
  - _Pooled cross-section_: multiple independent cross-sections combined and
    analyzed as a single dataset
    - E.g., multiple cross-sections treated as one large cross-section
    - E.g., combining student test score data from 2020, 2022, and 2024 into one
      regression

* Panel
- **Motivation**:
  - Most real-world interventions (policy, marketing, etc.) are difficult to
    randomize
    - E.g., in marketing it's difficult to control who receives the treatment
      (i.e., see your advertisement)
  - Panel data offers two sources of variation
    - _Across units_: compare treated and control cities (spatial variation)
    - _Across time_: compare pre- and post-treatment periods (temporal variation)

- **Key insight**: By tracking units over time, we can remove confounders that
  are fixed at the unit level
  - Even with unmeasured confounders, we can identify causal effects
  - This makes panel data _as good as it gets_ for observational causal
    inference

* Canonical Difference-in-Differences: The Setup

- **Notation**:
  - $D_i = 1$ if unit $i$ is treated, $0$ otherwise
  - $t \leq T_{pre}$ is pre-intervention period
  - $t > T_{pre}$ is post-intervention
  - $\text{Post}_t = 1$ if $t > T_{pre}$, otherwise $0$

- **Definition**:
  - The treatment indicator is $W_{it} = D_i \cdot \text{Post}_t$
    - Equals 1 only for treated units in post-treatment period

  - The outcome variable is $Y_{it}$ (e.g., number of downloads)
    - Observable for all unit-time combinations

  - The target is the Average Treatment Effect on the Treated (ATT), i.e., the
    effect of treatment on units that received it, after treatment takes place:
    $$
    \text{ATT} = \EE[Y_{it}(1) - Y_{it}(0) | D_i = 1, t > T_{pre}]
    $$

* DiD: Imputing the Counterfactual

- The missing piece is the treated counterfactual
  $$\EE[Y(0) | D = 1, \text{Post} = 1]$$
  which we estimate with:
  $$
  \begin{aligned}
    \EE[Y(0) | D = 1, Post = 1]
    &= \EE[Y | D = 1, Post = 0] \\
    &\quad + \left(
      \EE[Y | D = 0, Post = 1]
      - \EE[Y | D = 0, Post = 0]
    \right)
  \end{aligned}
  $$

- **Intuition**: Start with the treated baseline, add the control growth
  - _Treated baseline_: average outcome of treated units before treatment
  - _Control growth_: how much control units changed from pre to post
  - Assumption: This growth rate applies to treated units under the counterfactual

* Why Difference-in-Difference?

- Replacing the estimate in ATT:
  $$
  \begin{aligned}
    \text{ATT}
    &= \big[
      \EE[Y | D = 1, \text{Post} = 1]
      - \EE[Y | D = 1, \text{Post} = 0]
      \big] \\
    &\quad - \big[
      \EE[Y | D = 0, \text{Post} = 1]
      - \EE[Y | D = 0, \text{Post} = 0]
      \big]
  \end{aligned}
  $$
  - _First bracket_: treated group's change (pre to post)
  - _Second bracket_: control group's change (pre to post)
  - Difference of these two changes is the treatment effect
