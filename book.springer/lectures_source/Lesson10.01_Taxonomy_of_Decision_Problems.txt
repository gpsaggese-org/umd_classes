# Decision-Making Problem Categories

* Decision-Making Problem Categories: Overview

- **Goal**: build a _taxonomy_ of decision-making problems so the right
  algorithm can be matched to each problem
  - Every problem is a point in a structured space
  - Knowing its coordinates tells you which algorithms apply

- **Key idea**: decision problems vary along _10 orthogonal dimensions_
  - Each dimension asks one question about problem _structure_
  - The answers jointly determine tractability and method choice

- **Example**:
  - "Tic-Tac-Toe" is fully observable, multi-step, discrete, competitive,
    perfect-info, tabular
  - $\to$ solvable by Minimax or tabular Value Iteration

- **Remark**: same task can shift dimensions
  - E.g., add noise $\to$ becomes partially observable

* The 10 Structural Dimensions

1. _Observability_: What information is available to the agent
   - E.g., full, partial, hidden
2. _Time Horizon_: How far ahead the agent should plan
   - E.g., one-step, finite, infinite
3. _Action Space_: Type of actions available to the agent
   - E.g., discrete, continuous, hybrid
4. _Multi-Agent_: Number of agents and their objectives
   - E.g., single, cooperative, competitive
5. _Info Structure_: What information each player has access to
   - E.g., perfect, imperfect, asymmetric
6. _Model Knowledge_: Whether the agent knows the environment model
   - E.g., model-based, model-free
7. _Update Mechanism_: How the agent learns from experience
   - E.g., online, batch, replay
8. _Solution Concept_: How the optimal policy is computed or represented
   - E.g., value, policy, actor-critic, search
9. _Optimality Criterion_: Type of policy goal
   - E.g., deterministic, stochastic, optimal, approximate
10. _State-Action Space Size_: Scalability / complexity of the state-action
    space
   - E.g., tabular, linear function approximation, deep neural networks

* The 10 Structural Dimensions

# 1. Observability

* Fully Observable

- **Intuition**:
  - Agent sees the _complete state_ (all needed information is available each
    step)

::: columns
:::: {.column width=58%}

- **Definition**: modeled as an _MDP_ tuple
  $$(\mathcal{S}, \mathcal{A}, P, R, \gamma)$$
  - Observes full state $s_t \in \mathcal{S}$ each step
  - Dynamics $P(s'|s,a)$ and reward $R(s,a)$ fully known
  - No hidden state
::::
:::: {.column width=42%}

- **Example**: inventory management
  - Current stock observed
  - Demand known
  - Decide order quantity each period

- **Algorithms**: Q-Learning, SARSA, Value Iteration, Policy Iteration, MCTS

* Partially Observable

- **Intuition**:
  - Observations don't uniquely determine state
  - The system must track a _belief state_

::: columns
:::: {.column width=58%}
- **Definition**: modeled as a _POMDP_ tuple
  $$(\mathcal{S}, \mathcal{A}, P, R, \Omega, O, \gamma)$$
  - Observes $o_t \sim O(\cdot | s_t)$ (not the true state $s_t$)
  - Maintains belief
    $$b_t(s) = \Pr(s_t = s | o_1, a_1, \ldots, o_t)$$
::::
:::: {.column width=42%}

- **Example**: poker
  - See your own hand
  - Infer opponent hand distribution from betting behavior

- **Algorithms**: Particle Filtering, Kalman Filter, POMCP, Belief-State
  Planning

* Stochastic Observations with Hidden State

- **Intuition**:
  - Environment has a _hidden state_
  - Observations are noisy/corrupted, revealed only over time

- **Definition**: modeled as a _Hidden Markov Model_ (HMM)
  - Latent transition $\Pr(s_{t+1} | s_t)$
  - Noisy emission $o_t \sim O(\cdot | s_t)$
  - Goal: infer hidden sequence via filtering / smoothing

- **Example**: speech recognition
  - True phoneme sequence hidden
  - Observe noisy features
  - Infer phonemes

- **Example**: weather from noisy thermometer
  - Infer hot/cold/rainy from a drifting sensor over time

- **Algorithms**:
  - Hidden Markov Models
  - Kalman Filter (linear-Gaussian), Extended/Unscented KF (nonlinear), Particle
    Filters

# 2. Time Horizon

* One-Step

- **Intuition**:
  - No future consequences, no state transitions
  - Optimize _immediate reward only_

- **Definition**: _bandit_ problem over arms $a$
  $$\max_a \; \EE[R(a)] \quad\text{or learn}\quad \mu_a = \EE[R(a)]$$
  - Action and reward independent of history

- **Example**: online ad selection
  - Choose ad
  - Observe click/no-click,
  - Maximize click-through for current user

- **Example**: email spam filter
  - Classify one email
  - Decision affects only that email

- **Algorithms**: $\varepsilon$-Greedy, UCB (Upper Confidence Bound), Thompson
  Sampling, Contextual Bandits

* Finite Horizon

- **Intuition**:
  - A move cannot be judged in isolation, but must consider consequences over a
    fixed horizon $H$

- **Definition**: finite-horizon MDP solved by _backward induction_
  $$
  V_h(s)
    = \max_a
        \left[
          R(s,a) + V_{h-1}(s')
        \right]
  $$
  - Maximize $\sum_{t=0}^{H} R(s_t, a_t)$ with $s_{t+1} \sim P(\cdot|s_t,a_t)$

- **Example**: chess move selection
  - Look ahead 20+ moves to evaluate current move

- **Example**: grasp planning
  - Plan ~10-step gripper sequence to reach a feasible grasp

- **Algorithms**: Minimax, Alpha-Beta Pruning, A\*, RRT, MCTS

* Infinite Horizon

- **Intuition**:
  - Process never terminates
  - Balance immediate vs. long-term via discount $\gamma \in [0,1)$

- **Definition**: maximize discounted return, obeying the _Bellman equation_
  $$
  V^*(s)
    = \max_a
        \Big[
          R(s,a) + \gamma \, \EE_{s' \sim P(\cdot|s,a)}[V^*(s')]
        \Big]
  $$
  - Optimal policy $\pi^*$ is _stationary_ (time-invariant)

- **Example**: portfolio management
  - Allocate today to maximize wealth forever
  - Distant rewards down-weighted by $\gamma^t$

- **Algorithms**: Q-Learning, SARSA, Value/Policy Iteration, Actor-Critic;
  Deep RL — DQN, PPO, SAC

* Episodic / Finite Horizon

- **Intuition**:
  - Task runs for a _fixed episode length_ $T$
  - Then resets to an initial state

- **Definition**: episodic return (usually undiscounted)
  $$
  J = \EE\left[
    \sum_{t=0}^{T} R(s_t, a_t)
  \right]
  $$
  - Agent resets after step $T$ and next episode is independent

- **Example**: video-game level
  - Episode lasts exactly 300 frames
  - Maximize total score
  - Then the level ends

- **Example**: student studying for an exam
  - Fixed study time
  - Maximize exam score
  - Knowledge "resets" next episode

- **Algorithms**: Monte Carlo methods, MCTS, Policy Gradient (REINFORCE)

# 3. Action Space

* Discrete Actions

- **Intuition**:
  - Action set $\mathcal{A} = \{a_1, \ldots, a_n\}$ is _finite_
  - Can be enumerated

- **Definition**: pick the best action by enumeration
  $$
  a^* = \argmax_{a \in \mathcal{A}} Q(s, a)
  $$
  - $Q$-function is a table with $|\mathcal{S}| \times n$ entries

- **Example**: traffic light controller
  - Actions: $\{$Green-NS, Green-EW, Yellow, Red$\}$
  - Small branching factor

- **Example**: document recommendation
  - Actions: $\{$Like, Dislike, Bookmark, Share, Ignore$\}$
  - Learn $Q$ for each of 5 actions

- **Algorithms**: Q-Learning, DQN, MCTS, Minimax, Value Iteration

* Continuous Actions

- **Intuition**:
  - Action space $\mathcal{A} \subseteq \mathbb{R}^n$ is _uncountably infinite_
  - Cannot enumerate or tabulate

- **Definition**: learn a parameterized _function_, not a table
// TODO(ai_gp): Improve
  $$
  a = \mu(s) \;\text{(deterministic)} \quad\text{or}\quad a \sim \pi(a | s) \;\text{(stochastic)}
  $$
  - Approximated with neural networks

- **Example**: autonomous vehicle control
  - Steering: $\alpha \in [-\pi/4, \pi/4]$
  - Acceleration: $a \in [-10, 5]$ m/s$^2$

- **Example**: robot arm
  - Continuous joint angles: $(\theta_1, \theta_2, \theta_3) \in \mathbb{R}^3$

- **Algorithms**: DDPG, TD3, SAC, PPO (continuous), Policy Gradient,
  Evolutionary Strategies

* Hybrid (Mixed Discrete-Continuous)

- **Intuition**:
  - Some actions _discrete_, some _continuous_
  - Two-level hierarchical decision

- **Definition**: factorize the policy over a discrete then a continuous action
  $$
  \pi(a_d, a_c | s)
    = \pi_{discrete}(a_d | s)\, \pi_{continuous}(a_c | s, a_d)
  $$
  - Continuous choice $a_c$ conditioned on discrete choice $a_d$

- **Example**: manufacturing robot
  - Discrete: select tool (gripper, welder, sprayer)
  - Continuous: trajectory speed and position

- **Example**: robotic gripper
  - Discrete: which of 5 objects
  - Continuous: grasp force and angle

- **Algorithms**: Branching DQN, Hierarchical RL, Multi-task Learning with
  shared base

# 4. Multi-Agent Interaction

* Single-Agent

- **Intuition**:
  - _One_ decision-maker, _one_ objective
  - No strategic interaction
  - Environment is stochastic but non-adversarial

- **Definition**: a standard MDP with optimal $\pi^*$ satisfying Bellman equation
  $$
  J = \EE\left[
    \sum_t \gamma^t R(s_t, a_t)
  \right]
  $$
  - No game theory needed

- **Example**: personalized movie recommendation
  - One system, one user
  - Maximize user satisfaction

- **Example**: Inventory Management
  - One company minimizes cost + stockout penalties

- **Algorithms**: Q-Learning, DQN, SARSA, PPO, Actor-Critic

* Multi-Agent Cooperative

- **Intuition**:
  - $n$ agents share _one objective_
  - Must _coordinate_ actions

- **Definition**: cooperative multi-agent MDP with a _shared_ reward
  $$
  J = \EE\left[
    \sum_t R(s_t, a_{1,t}, \ldots, a_{n,t})
  \right]
  $$
  - Challenge: _decentralized execution_ via communication / parameter sharing

- **Example**: warehouse robot team
  - 5 robots minimize delivery time
  - Avoid collisions and deadlocks under one team reward

- **Example**: vehicle network optimization
  - Cooperatively route packets
  - Maximize throughput (minimize delay)

- **Algorithms**: QMIX, MAPPO, MAAC, MADDPG, CommNet

* Multi-Agent Competitive

- **Intuition**:
  - Agents have _conflicting_ objectives
  - Game theory and _Nash equilibrium_ apply

- **Definition**:
  - Each agent $i$ maximizes $J_i$
  - At a Nash equilibrium no unilateral deviation helps
    $$
    R_i(s, \pi_i^*, \pi_{-i}^*)
      \geq R_i(s, \pi_i, \pi_{-i}^*) \quad \forall \pi_i
    $$
  - Zero-sum special case: $R_1 + R_2 = \text{const}$

- **Example**: chess match
  - Two players, zero-sum
  - Optimal play is a Nash equilibrium

- **Example**: auction bidding
  - Your gain is others' loss
  - Truthful bidding is equilibrium in a second-price auction

- **Algorithms**: Minimax + Alpha-Beta, Self-Play, CFR, Nash Solvers

# 5. Information Structure

* Perfect Information

- **Intuition**:
  - All players know _all_ relevant information
  - Entire game tree is visible
  - No hidden moves

- **Definition**: every information set is a _singleton_
  $$
  I_i(h) =
    \left\{
      h' : \text{player } i \text{ cannot distinguish } h \text{ from } h'
    \right\}
  $$
  - Optimal play by _backward induction_ on the game tree

- **Example**: Chess
  - Both players see the board and full move history

- **Example**: tic-tac-toe
  - Fully solvable: all Nash equilibria via Minimax

- **Algorithms**: Minimax + Alpha-Beta, Negamax, MCTS, AlphaZero, exact solvers

* Imperfect Information

- **Intuition**:
  - There are hidden moves or hidden state
  - Create an _information gap_ between players

- **Definition**: non-singleton information sets $\to$ act on _beliefs_
  $$
  b_i(h) =
    \Pr\left(
      h \,\Big|\, \text{player } i\text{'s observations}
    \right)
  $$
  - Equilibrium is a _mixed strategy_ $\sigma_i^*$ with no profitable deviation

- **Example**: Poker
  - Betting history visible but hole cards hidden
  - Asymmetry drives strategy

- **Example**: business competition
  - Firms price without knowing rivals' costs
  - Randomize to avoid exploitation

- **Algorithms**: CFR (Counterfactual Regret Minimization), Regret Matching,
  Nash Solvers, Information-Set Abstraction

* Asymmetric Information

- **Intuition**:
  - Players have _fundamentally different_ information sets and capabilities
  - One side cannot observe the other

// TODO(ai_gp): Unclear
- **Definition**: principal designs a contract to align an unobserved agent
  $$
  \max_{c}
    \Big[ u_1(c(y)) - c(y) \Big]
  \quad \text{s.t.} \quad
  a_2^* = \arg\max_a
    \big[
      u_2(c(y(a))) - \psi(a)
    \big]
  $$

- **Example**: principal-agent
  - Employer sees output, not employee effort
  - Must incentivize

- **Example**: insurance market
  - Buyer knows its health, insurer does not (adverse selection)
  - Screen via deductibles

- **Algorithms**: Mechanism Design, Bayesian Games, Signaling Equilibria,
  Information-dependent policies

# 6. Model Knowledge

* Model-Based

- **Intuition**:
  - Agent _has_ (or _learns_) a world model
  - Then _plans_ against it without touching the real environment

- **Definition**: solve planning on learned $\hat{P}, \hat{R}$
  $$
  V(s)
    = \max_a
        \left[
          \hat{R}(s,a) + \gamma \, \EE_{s' \sim \hat{P}}[V(s')]
        \right]
  $$
// TODO(ai_gp): Add description
  - Pros
    - Sample-efficient
  - Cons
    - sensitive to model error

- **Example**: GPS route planner
  - Model of roads and travel times
  - Finds fastest route without driving all routes

- **Example**: game AI lookahead
  - Simulate future states
  - Avoid risky actions in simulation

- **Algorithms**: Value/Policy Iteration, Dyna-Q, MCTS, AlphaGo, MuZero

* Model-Free

- **Intuition**:
  - Agent has _no model_ and learns directly from experience by trial-and-error

- **Definition**: learn value/policy from transitions
  $(s_t, a_t, r_t, s_{t+1})$
  $$
  Q(s, a)
    \leftarrow Q(s,a) + \alpha \left[
      r + \gamma \max_{a'} Q(s', a') - Q(s,a)
    \right]
  $$
  - No explicit $\hat{P}$ or $\hat{R}$; _asymptotically optimal_ but data-hungry

- **Example**: Atari from pixels
  - No game code
  - Learn $Q$ from screen + rewards

- **Example**: robot grasping
  - Learn from grasp success/failure
  - No physics model

- **Algorithms**: Q-Learning, SARSA, REINFORCE, Actor-Critic, DQN, PPO, SAC, A3C

# 7. Update Mechanism

* Online Learning

- **Intuition**:
  - Learn and act in _real time_ on a single trajectory
  - Each sample used _once_
  - No buffer

- **Definition**: immediate on-policy update after each transition
  $$
  \theta_t \to \theta_{t+1}
    \quad\text{from}\quad (s_t, a_t, r_t, s_{t+1})
  $$
  - High variance, low memory, must handle _non-stationary_ data

- **Example**: autonomous vehicle braking
  - Learn immediately while driving
  - Cannot wait for batch processing

- **Example**: live customer support
  - Update after each interaction
  - Use satisfaction feedback

- **Algorithms**: SARSA, TD Learning, REINFORCE, on-policy Actor-Critic (A3C)

* Batch Learning / Offline RL

- **Intuition**:
  - Train on a _fixed dataset_ with _no_ environment interaction
  - All data collected in advance

- **Definition**: optimize over a static dataset
  $$\mathcal{D} = \{(s_i, a_i, r_i, s_i')\}$$
  - Core challenge: _off-policy_ data $\to$ _distribution shift_
  - Fixes: importance sampling, conservative value estimates

- **Example**: medical treatment policy
  - Learn from historical (state, treatment, outcome)
  - Cannot experiment on new patients

- **Example**: movie recommendation
  - Train on historical interactions
  - Avoid bad recommendations in production

- **Algorithms**: Batch Q-Learning, Offline RL, Behavior Cloning, Conservative
  Q-Learning (CQL)

* Replay-based / Experience Replay

- **Intuition**:
  - Store experiences in a buffer and _replay_ them
  - Combines online acting with batch updates
  - _Decorrelates_ samples

- **Definition**: maintain buffer $\mathcal{B}$ of size $N$; each step
  1. Act via $\pi_t$, add $(s_t, a_t, r_t, s_{t+1})$ to $\mathcal{B}$
  2. Sample a minibatch from $\mathcal{B}$
  3. Update $\theta$ on the minibatch
  - Benefits: breaks correlation, reuses samples, enables off-policy learning

- **Example**: DQN on Atari games
  - Store frames
  - Train on random minibatches from the replay buffer

- **Algorithms**: DQN with Experience Replay, Prioritized ER (PER), Hindsight ER
  (HER), Rainbow DQN

# 8. Solution Concept

* Value-based Methods

- **Intuition**:
  - Learn _values_, then act _greedily_
  - No explicit policy is stored

- **Definition**: learn $Q$ (or $V$), derive $\pi(s) = \arg\max_a Q(s,a)$
  $$
  Q(s,a)
    \leftarrow Q(s,a) + \alpha \left[
      r + \gamma \max_{a'} Q(s', a') - Q(s,a)
    \right]
  $$
  - _Off-policy_ and sample-efficient

- **Example**: chess position evaluator
  - Score each board
  - Play the move to the highest-value position

- **Example**: traffic signal control
  - $Q(\text{state}, \text{signal})$ predicts queue reduction

- **Algorithms**: Q-Learning, Value Iteration, DQN, Double DQN, Dueling DQN

* Policy-based Methods

- **Intuition**:
  - Learn the _policy directly_
  - No intermediate value function needed

- **Definition**: parameterize $\pi_\theta(a | s)$, ascend the policy gradient
  $$
  \nabla_\theta J
    = \EE\left[
      \nabla_\theta \log \pi_\theta(a | s)\, Q(s,a)
    \right]
  $$
  - Handles continuous actions; _higher variance_; on-policy

- **Example**: robot arm joint control
  - Output a distribution over joint angles
  - Explore continuous actions naturally

- **Example**: game NPC strategy
  - Learn a stochastic strategy (aggressive / defensive / evasive)
  - Unpredictable to the player

- **Algorithms**: REINFORCE, PPO, TRPO, Natural Policy Gradient, Evolutionary
  Strategies

* Actor-Critic Methods

::: columns
:::: {.column width=58%}
- **Intuition**:
  - Combine both — an _actor_ picks actions, a _critic_ evaluates them
  - Critic reduces the actor's variance

- **Definition**: actor $\pi_\theta$, critic $V_\phi$, using advantage
  $$
  A(s,a)
    = r + \gamma V_\phi(s') - V_\phi(s)
  $$
  - Actor update: $\nabla_\theta \log \pi_\theta(a|s)\, A(s,a)$

  - Critic predicts forward progress
  - Lower variance than pure policy gradient

- **Algorithms**: A2C, A3C, SAC, DDPG, TD3, PPO (value baseline)

* Search / Planning Methods

- **Intuition**:
  - _Look ahead_ by building a tree at decision time
  - Use a model or simulator before committing

- **Definition**: expand a tree, evaluate leaves, backprop, select by UCB
  $$
  a^* = \arg\max_a
    \left[
      \frac{Q(s,a)}{N(s,a)} + c \sqrt{\frac{\ln N(s)}{N(s,a)}}
    \right]
  $$
  - Sample-heavy but _asymptotically optimal_

- **Example**: AlphaGo game playing
  - MCTS searches the game tree
  - Evaluates leaves with a neural network before each move

- **Example**: robot task planning
  - Search 5-10 steps ahead
  - Backtrack from failure states

- **Algorithms**: MCTS, Minimax + Alpha-Beta, A\*, MPC, AlphaZero, MuZero

# 9. Optimality Criterion

* Deterministic Policies

- **Intuition**:
  - One _fixed action_ per state
  - Randomness appears only during exploration in training

- **Definition**: deterministic map $\mu(s) \in \mathcal{A}$ with gradient
  $$
  \nabla_\theta J
    = \EE\left[
      \nabla_a Q(s,a)\, \nabla_\theta \mu_\theta(s) \big|_{a=\mu_\theta(s)}
    \right]
  $$
  - Off-policy, sample-efficient; exploration via noise injection

- **Example**: traffic light controller
  - Heavy left traffic → green left
  - Always the same action

- **Example**: robot end-effector control
  - Vision input maps to a fixed target gripper position
  - Used at deployment

- **Algorithms**: DPG, DDPG, TD3, greedy Q-Learning, Minimax

* Stochastic Policies

- **Intuition**:
  - Output a _distribution_ over actions
  - Exploration is _built into_ the policy

- **Definition**: sample $a \sim \pi(\cdot | s)$ and follow the policy
  gradient
  $$
  \nabla_\theta J
    = \EE_{a \sim \pi}\left[
      \nabla_\theta \log \pi_\theta(a | s)\, Q(s,a)
    \right]
  $$
  - Handles _multimodal_ actions; more stable

- **Example**: card-game strategy
  - Aggressive: 30%, conservative: 70%
  - Stay unpredictable

- **Example**: diverse recommender
  - Sample: news 40%, entertainment 30%, educational 30%
  - Avoid local optima

- **Algorithms**: REINFORCE, PPO, A3C, SAC, Thompson Sampling

* Optimal Policies

- **Intuition**:
  - Find the _provably best_ policy — exact or $\varepsilon$-optimal
  - Even if computationally expensive

- **Definition**: $\pi^* = \arg\max_\pi J(\pi)$ with optimal value satisfying
  Bellman
  $$
  V^*(s)
    = \max_a
        \left[
          r(s,a) + \gamma \, \EE[V^*(s')]
        \right]
  $$
  - Value Iteration _converges_ in finite MDPs

- **Example**: chess solver
  - Prove a move is optimal from a given position

- **Example**: trajectory optimization
  - Globally optimal path (e.g., power-minimal route)
  - For convex cost

- **Algorithms**: Value/Policy Iteration, Minimax + Alpha-Beta, AlphaZero,
  Exhaustive Search

* Approximate / Satisficing Policies

- **Intuition**:
  - Accept a _good-enough_ policy with _bounded_ suboptimality
  - When time or compute is limited

- **Definition**: $\varepsilon$-optimal policy with a guarantee
  $$
  V^\varepsilon(s)
    \geq V^*(s) - \varepsilon
  $$
  - Bounded-depth search: error $\leq \varepsilon / (1 - \gamma)$; _anytime_
    algorithms stop early

- **Example**: real-time chess engine — search a fixed depth within the time
  limit; suboptimal but practical

- **Example**: robot obstacle avoidance — must react in 50 ms; greedy/myopic
  avoidance, safe not optimal

- **Algorithms**: Anytime Algorithms, Approximate Dynamic Programming, Bounded
  Suboptimality, Satisficing methods

# 10. State - Action Space Size

* Small Tabular Problem

- **Intuition**:
  - $|\mathcal{S}|$ and $|\mathcal{A}|$ are small enough to store in a _lookup table_ (e.g., < 10k states)

- **Definition**: $Q$-table is a $|\mathcal{S}| \times |\mathcal{A}|$ matrix
  $$
  V(s)
    \leftarrow \max_a
      \Big[
        R(s,a) + \gamma \sum_{s'} P(s'|s,a)\, V(s')
      \Big]
  $$
  - _Exact_ solution with guaranteed convergence

- **Example**: grid world
  - $10 \times 10$ grid = 100 states, 4 actions
  - Full $Q$-table fits

- **Example**: small inventory
  - 20 levels $\times$ 5 order quantities
  - Solve by tabular Q-learning

- **Algorithms**: Tabular Q-Learning, Tabular Value/Policy Iteration, MCTS

* Medium: Linear Function Approximation

- **Intuition**:
  - State space _too large_ for a table
  - Compress via features

- **Definition**: linear value in a feature vector $\phi(s) \in \mathbb{R}^d$,
  $d \ll |\mathcal{S}|$
  $$
  V(s) \approx w^\top \phi(s)
  $$
  $$
  w \leftarrow w + \alpha \left[
    r + \gamma V(s') - V(s)
  \right] \phi(s)
  $$
  - _Basis-function design_ is the key challenge

- **Example**: adaptive auction bidding
  - Features: price history, competitor bids, budget remaining
  - Too many to tabulate

- **Example**: online resource allocation
  - Features: load, queue length, time of day, priority

- **Algorithms**: Q-Learning / SARSA with FA, LSTD, Linear/Contextual Bandits

* Large: Deep Neural Networks

- **Intuition**:
  - _High-dimensional_ inputs (images, speech)
  - Demand a learned feature extractor

- **Definition**: value as a deep network $V(s) = f_\theta(s)$
  $$
  \theta \leftarrow \theta + \alpha \left[
    r + \gamma \max_{a'} f_{\theta'}(s') - f_\theta(s)
  \right] \nabla_\theta f_\theta(s)
  $$
  - Challenges: non-stationary targets, off-policy data
  - Fixes: _experience replay_, _target networks_

- **Example**: self-driving car
  - Camera image: 1920 x 1440 x 3
  - CNN features → continuous control

- **Example**: Atari games
  - $84 \times 84 \times 3$ screen
  - CNN extracts sprites and terrain
  - DQN learns $Q$

- **Algorithms**: DQN (Double / Dueling / Rainbow), A3C, PPO, TRPO, SAC, TD3

* Key Takeaways

- **Key idea**: locate a problem on the _10 dimensions_, then read off the
  algorithm family

- **Observability + Model**: full obs. $\to$ direct learning; partial $\to$
  belief tracking; model-based is sample-efficient, model-free is
  asymptotically optimal

- **Horizon + Actions**: myopic $\to$ bandits; multi-step $\to$ search; infinite
  $\to$ stationary policy; discrete $\to$ enumerate, continuous $\to$ learn a
  distribution

- **Agents + Information**: single $\to$ standard RL; competitive $\to$ Nash /
  game theory; imperfect info $\to$ CFR; asymmetric $\to$ mechanism design

- **Solution + Optimality + Scale**: value / policy / actor-critic / search;
  optimal vs. satisficing; tabular $\to$ linear FA $\to$ deep NN as dimension
  grows

- **Remark**: the dimensions are _orthogonal_ — changing one (e.g., adding
  noise, more agents) moves the problem and its method independently
