#### Amazon Web Services (AWS)
- **\textcolor{red}{AWS is a platform offering complete cloud solutions}**
  - Computing (e.g., EC2)
  - Storage (e.g., S3)
  - Networking

- **\textcolor{darkgreen}{Offers different levels of abstraction}**
  - IaaS, PaaS, SaaS
  - From virtual hardware to applications, e.g.,
    - Host websites
    - Run enterprise software
    - Run machine learning applications

- **\textcolor{blue}{Control services in different ways}**
  - Web interface (console)
  - CLI: \textcolor{blue}{\texttt{aws}} command
  - Language libraries, SDKs (e.g., Python \textcolor{blue}{\texttt{boto3}})

#### AWS as Business
::: columns
:::: {.column width=50%}
- Services charge a pay-per-use pricing model
  - 500 new services and features added annually

- Data centers distributed globally
  - US, Europe, Asia, South America

- Extremely profitable
  - $91B/year in revenue (2023)
  - Grows 42% year-over-year
  - Controls 30% of the cloud business

#### Types of Cloud Computing
- Cloud computing enables a **\textcolor{red}{shared pool of configurable computing resources}**
  - E.g., servers, storage, networks, applications, services
  - Accessible from anywhere
  - Convenient
  - On-demand

- Clouds can be:
  - _Public_: open to the general public (e.g., AWS)
  - _Private_: virtualize and share IT infrastructure within one organization
    (e.g., government)
  - _Hybrid_: mix of public and private clouds

#### AWS vs Google Cloud vs Microsoft Azure
::: columns
:::: {.column width=60%}
- **\textcolor{red}{Similarities:}**
  - Worldwide infrastructure
  - Provide IaaS (computing, networking, storage)
    - AWS EC2 / Google Compute Engine / Azure VMs
    - AWS S3 / Google Cloud Storage / Azure Blob Storage
  - Pay-as-you-go pricing model

- **\textcolor{blue}{Differences:}**
  - AWS
    - Market leader, mature, powerful
    - Utilizes open source technologies
  - Azure
    - Offers Microsoft stack in the cloud
  - Google
    - Focuses on cloud-native applications

#### Capacity Scaling
::: columns
:::: {.column width=50%}
- **\textcolor{red}{No need to plan for capacity}**
  - Do not predict capacity
  - Schedule capacity on-the-fly
  - No concern for rack space, switches, power supplies
  - Add more VMs (1 to 1000) and storage (GB to PB) as needed

- **\textcolor{darkgreen}{Handle seasonal traffic by scaling up/down}**
  - Day vs night
  - Weekday vs weekend
  - Holidays
  - No test system needed when the team is off

::: columns

    - For a scalable workload "buy 1 server for 1000 hours" = "buy 1000 servers

#### Accounts and Users
::: columns
:::: {.column width=55%}
- **\textcolor{red}{Users}**
  - One root AWS account
  - Attach multiple users to an account
    - Different privileges
    - Isolate workloads

- **\textcolor{darkgreen}{Be safe}**
  - Never use root account to develop
  - Always use 2FA
  - Avoid costly mistakes

- **\textcolor{blue}{Key pair}**
  - Create a key pair to access a virtual server
  - Public key (stored in AWS and on virtual servers)
  - Private key is your secret
    - Don't lose it; it can't be retrieved

#### AWS VMs
::: columns
:::: {.column width=55%}
- **\textcolor{red}{With virtualization}**
  - Multiple VMs run on the same hardware
  - Start and stop VMs on-demand

- **\textcolor{darkgreen}{Physical server}**
  - Aka "host machine", "bare metal"
  - Consists of CPUs, memory, networking interfaces, storage

- **\textcolor{blue}{Hypervisor}**
  - Software + CPU hardware
  - Isolates guests
  - Schedules hardware requests

- AWS
  - Used Xen hypervisor (open-source) before
  - Switched to AWS Nitro
    - Hardware-assisted virtualization
    - Performance close to bare metal

- **\textcolor{violet}{Virtual servers}**
  - Isolated on the same hardware

#### States of a VM
- **\textcolor{red}{Start}**
  - Start stopped VM

- **\textcolor{darkgreen}{Stop}**
  - Stopped VM not billed
  - Network HDD persists and incurs charges
  - Local disk does not persist
  - VM can restart on a different host (different IP)

::: columns
:::: {.column width=45%}

- **\textcolor{blue}{Reboot}**
  - Network HDD persists
  - Local disk does not persist
  - Software remains installed
  - VM restarts on a different host

- **\textcolor{violet}{Terminate}**
  - Delete: cannot restart
  - Network HDD persists
  - Local disk wiped out

#### Moving / Upgrading EC2 Instances
- **\textcolor{red}{Scale up / down}**
  - Increase VM size for more computing power
  - Stop VM
  - Change instance type (e.g., \textcolor{blue}{\texttt{m3.large}})
  - Start VM
  - IP addresses change

- **\textcolor{darkgreen}{AWS regions}**
  - Regions are collections of data centers
  - Regions are independent
  - No automatic data transfer across regions
  - Some services (e.g., IAM, CDN, DNS) are global

- **\textcolor{blue}{Why move across AWS regions}**
  - Proximity to users
  - Compliance
    - Data storage and processing permissions
  - Service availability
    - Some services unavailable in certain regions
  - Redundancy
  - Costs
    - Vary by region

#### Optimizing Costs
- **\textcolor{red}{On-demand instances}**
  - Maximum flexibility, no restrictions
  - Start and stop VMs anytime
  - Pay by hour

- **\textcolor{darkgreen}{EC2 / Compute saving plans}**
  - 1 yr vs 3 yrs
  - Commit to a certain number of hours
  - Payment options: all, partial, no upfront
  - Discount: up to 3x cheaper than on-demand
  - Useful for dev servers

- **\textcolor{blue}{Capacity reservation}**
  - Access machines even in peak hours

- **\textcolor{violet}{Spot instances}**
  - Bid for unused capacity
  - Price based on supply/demand
  - Discount: up to 10x cheaper than on-demand
  - Useful for asynchronous tasks

#### Low-Cost Processing
- Lots of batch jobs are not critical / run on a schedule
  - Analyze data daily
  - Generate reports from a database

1. **\textcolor{red}{Allocate machines on demand}**
   - AWS bills VMs per minute
   - Pay only when running jobs

2. **\textcolor{darkgreen}{AWS Batch}**
   - Offers spare capacity at a discount
   - Runs when capacity is available, saving 50%

3. **\textcolor{blue}{AWS Lambda}**
   - Serverless

#### Infrastructure-as-Code
- Use high-level **\textcolor{red}{programming language to control IT systems}**

- Apply **\textcolor{darkgreen}{software development principles to infrastructure}**
  - Code repository
  - Automated tests
  - Continuous integration

- **\textcolor{blue}{DevOps (SRE in Google parlance)}**
  - Mix developers and operations in the same team
  - Use software to bring development and operations closer
  - Switch roles to experience each other's challenges
    - Devs $\to$ responsible for operational tasks (e.g., on-call)
    - Ops $\to$ involved in software development, making systems easier to
      operate
  - Foster communication and collaboration

#### Infrastructure-as-Code: Advantages
::: columns

- **\textcolor{red}{Save time}**

  - Automate tasks

  - Push-button flow

- **\textcolor{darkgreen}{Consistency of actions}**

- **\textcolor{teal}{Deployment pipeline}**
  - Commit changes to source code

  - Automatic tests (e.g., integration tests)
  - Build testing environment

  - Propagate changes to production

- **\textcolor{cyan}{Scripts as detailed documentation}**

#### AWS Command Line Interface (CLI)
- Provides a **\textcolor{red}{unified interface}** to all AWS services
  - Output is in JSON format
  ```bash
  > apt-get install awscli
  ```

- **\textcolor{darkgreen}{Authenticate}**
  ```bash
  > aws configure
  ```
  - AWS access key ID
    - E.g., \textcolor{blue}{\texttt{AKIAIR...D7ZCA}}
  - AWS secret access key
    - E.g., \textcolor{blue}{\texttt{SSKIng7jkA...enqBj7}}
  - Default region name
    - E.g., \textcolor{blue}{\texttt{us-east-1}}

- **\textcolor{blue}{Execute command}**
  ```bash
  > aws <service> <action> --key value
  ```

#### AWS CloudFormation
- **\textcolor{red}{Use templates to describe infrastructure}**
  - E.g., JSON, YAML

- **\textcolor{darkgreen}{Declarative vs imperative approach}**
  - Declare the system, not the steps to build it

- **\textcolor{blue}{AWS Stacks}** processes CloudFormation templates

- **\textcolor{violet}{Pros}**
  - Consistent infrastructure description
  - Handles dependencies
  - Customizable
    - Inject parameters to customize templates
  - Testable
    - Create infrastructure from a template, test, shut down
  - Updatable
    - Update template, Stacks apply changes automatically
  - Serves as documentation
    - Use as code in source control

#### Securing Your System
::: columns
:::: {.column width=50%}
- **\textcolor{red}{Always install software updates}**
  - Fix security vulnerabilities promptly

- **\textcolor{darkgreen}{Restrict access to AWS account}**
  - Use separate AWS accounts for individuals and scripts
  - Apply "least privilege": grant only necessary permissions

- **\textcolor{blue}{Restrict network traffic}**
  - Open essential ports
    - E.g., 80 for HTTP, 443 for HTTPS
  - Close others
  - Encrypt traffic and data

- **\textcolor{violet}{Create a private network}**

#### AWS Shared-responsibility Principle
- **\textcolor{red}{AWS is responsible for}**:
  - Protecting the network by monitoring Internet access
  - Preventing DDoS attacks
  - Ensuring the physical security of data centers
  - Decommissioning storage devices after end of life

- **\textcolor{blue}{You are responsible for}**:
  - Restricting access using IAM
  - Encrypting network traffic (e.g., HTTPS)
  - Configuring firewalls and VPNs
  - Encrypting data
  - Updating the OS and software
